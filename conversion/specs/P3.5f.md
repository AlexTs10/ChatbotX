- Generator: `conversion/tools/rpc-table-gen/gen.mjs` (TypeScript compiler
  API, static scan; no module runs). It follows `lazy(import(...))`, spreads,
  re-exports, default imports, local helpers that return a chain
  (`memberAPI(schema)`) and `X.use(...).router(...)`. Per procedure: auth
  base, `.route({ method })`, the `workspaceAuthorizedMidddleware` mapper path
  and whether `.input()` comes before that `.use()`. Result: 274 procedures,
  all `authorizedAPI`, 264 with a workspace mapper (all `input.workspaceId`).
  Run: `TS=<node_modules/typescript> node conversion/tools/rpc-table-gen/gen.mjs`.
- Call order: unknown top-level key -> `404 text/plain "Not found"`; session
  (401) -> `mustChangePassword` (403) -> workspace check: the mapped id must be
  a digit string (else 400 `BAD_REQUEST "Input validation failed"` when the
  input is validated first, else 401) -> membership (401) -> deletion
  scheduled (403) -> handler (ported) or `404 NOT_FOUND "Operation not ported
  yet"`.
- Output: `{ "json": <output> }` (no `meta`: the ported outputs hold no Date,
  bigint or undefined). A handler error is RPC-encoded like the auth errors.

Tests: `crates/api/tests/rpc_procedures.rs` — 7 ported rows (3 files, all
`adapted`) + 7 Rust-native (table, order, not-ported fallback, realtime mint).

## Decisions

- (slice 1) A procedure name that is not in the table, under a known key,
  keeps the P3.5d behaviour (session auth, workspace check when the input has
  a string `workspaceId`, then "not ported"). The original answers 404 "Not
  found" (no match), but the locked `rpc_session_auth.rs` tests call
  placeholder names (`contactsAPIs/list`). Recommended option: keep them green.
- (slice 1) `rpc_router(AuthState)` stays (auth only, no handlers);
  `rpc_router_with(RpcState)` adds the handlers. The server uses the second.
- (slice 1) The input validation error carries no zod `issues` (`data`).
- (slice 1) `findPoll` has no `assertCurrentUserCanAccessChatbot` (no RSC
  layer in the Rust server; the caller checks access).

## Behaviour differences

1. (slice 1) Only the workspace id of the input is validated before the
   handler; the other input fields of an unported procedure are not checked.
2. (slice 1) The owner quota gate (`assertWorkspaceOwnerAccessForMethod`) and
   support-access sessions are not ported (as P3.5d).
