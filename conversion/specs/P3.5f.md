# P3.5f — auth rest (porter spec)

Unit (TRACKER P3.5f; P3.5.md §10–12 "not done" lists; DECISIONS 2026-11-13 and
2026-11-16 "moved to P3.5f"). Slices, each a stage 1 / stage 2 commit pair:

1. `/rpc` procedure table + the moved `/rpc` items (`poll-queries`,
   `places-near-me-category-options`, `list-questionnaires-for-flow-api`) and
   the session `realtimeAPI.mintWorkspaceConnectTokenAuthenticatedAPI`.
2. Mobile auth: `/api/auth/mobile/*`, JWT signing (EdDSA, `"Jwk"` rows),
   `GET /api/auth/jwks`, the mobile principal, `realtime.getConnectToken`.
3. The rest of `packages/auth` tests, OAuth endpoints, social sign-in,
   anonymous sessions, support access (as far as the context allows).

## 1. Slice 1 — `/rpc` procedure table

| TypeScript | Rust (`chatbotx_api::…`) |
|---|---|
| `routers/index.ts` (79 keys, 274 procedures) | `rpc::{RPC_PROCEDURES, RpcProcedure, RpcAuth, find_procedure}` (`rpc/table.rs`, generated) |
| `app/rpc/[[...rest]]/route.ts` + `authMiddleware` + `workspaceAuthorizedMidddleware` | `rpc::{rpc_router, rpc_router_with, RpcState, RpcContext, RpcWorkspace}` |

| `realtimeAPI.mintWorkspaceConnectTokenAuthenticatedAPI`, `mintMemberConnectToken`, `conversationMemberScope.resolve` | `rpc::procedures::mint_member_connect_token` |
| `features/polls/queries` `findPoll` | `rpc::procedures::find_poll` |

- Generator: `conversion/tools/rpc-table-gen/gen.mjs` (TypeScript compiler
  API, static scan; no module runs). It follows `lazy(import(...))`, spreads,
  re-exports, default imports, local helpers that return a chain
  (`memberAPI(schema)`) and `X.use(...).router(...)`. Per procedure: auth
  base, `.route({ method })`, the `workspaceAuthorizedMidddleware` mapper path
  and whether `.input()` comes before that `.use()`. Result: 274 procedures,
  all `authorizedAPI`, 264 with a workspace mapper (all `input.workspaceId`).
  Run: `TS=<node_modules/typescript> node conversion/tools/rpc-table-gen/gen.mjs`.
- Call order: unknown top-level key -> `404 text/plain "Not found"`; session
  (401) -> `mustChangePassword` (403) -> workspace check: the mapped id must be
  a digit string (else 400 `BAD_REQUEST "Input validation failed"` when the
  input is validated first, else 401) -> membership (401) -> deletion
  scheduled (403) -> handler (ported) or `404 NOT_FOUND "Operation not ported
  yet"`.
- Output: `{ "json": <output> }` (no `meta`: the ported outputs hold no Date,
  bigint or undefined). A handler error is RPC-encoded like the auth errors.

Tests: `crates/api/tests/rpc_procedures.rs` — 7 ported rows (3 files, all
`adapted`) + 7 Rust-native (table, order, not-ported fallback, realtime mint).

## 2. Slice 2 — session paths of the web UI (moved first, user 2026-11-16)

| TypeScript / better-auth | Rust (`chatbotx_api::session::…`) |
|---|---|
| better-auth `updateUser` (`authClient.updateUser`, profile dialog) | `POST /api/auth/update-user` -> `{ status: true }` |
| better-auth `changePassword` + `mobileAuth` after hook | `POST /api/auth/change-password` -> `{ token, user }` |
| `features/auth/actions/force-change-password.ts` (server action) | `force_change_password`, served as `POST /rpc/authActions/forceChangePassword` |
| `user.additionalFields` + `anonymous()` user field | `get-session` / sign-in `user` now has `isAnonymous`, `mustChangePassword` |

- `update-user`: session required (401 `UNAUTHORIZED` "Unauthorized");
  `email` -> 400 `EMAIL_CAN_NOT_BE_UPDATED`; `tenantId` / `mustChangePassword`
  / `isAnonymous` -> 400 "<field> is not allowed to be set"; no `name` and no
  `image` -> 400 "No fields to update". Origin check as every auth POST.
- `change-password`: length checks (`PASSWORD_TOO_SHORT` / `_TOO_LONG`), no
  credential account -> `CREDENTIAL_ACCOUNT_NOT_FOUND`, wrong current password
  -> `INVALID_PASSWORD` (400). `revokeOtherSessions: true` deletes every
  session of the user and sets a new session cookie (+ `set-auth-token`).
  Always revokes the user's mobile refresh tokens (`mobileAuth` hook).
- `/rpc/authActions/forceChangePassword` input (`{ json }`):
  `{ currentPassword, newPassword, passwordConfirmation }` (8–100 chars,
  confirmation equal, new != current; else 400 `BAD_REQUEST "Input validation
  failed"`). It runs before the `mustChangePassword` gate. No session -> 401
  `unauthorized "Not authenticated"`; a better-auth error -> 400
  `changePasswordFailed` with its message. Success: `{ "json": { "ok": true } }`
  + the rotated session cookie; `mustChangePassword` is cleared.

Tests: `crates/api/tests/session_account.rs` — 7 Rust-native (no TS test
covers these endpoints).

| TypeScript / better-auth | Rust (`chatbotx_api::session::…`) |

- Sign-in: origin check (callback URLs), provider lookup (404
  `PROVIDER_NOT_FOUND`), state row `Verification` `auth-state:<state>` with
  `{ callbackURL, codeVerifier, errorURL?, newUserURL?, expiresAt, oauthState,
  requestSignUp? }` (10 minutes), authorization URL (`response_type`,
  `client_id`, `state`, `scope` space-joined, pinned `redirect_uri`, PKCE S256
  for Google and the generic provider, Google `include_granted_scopes=true`),
  `{ url, redirect }` + `Location` unless `disableRedirect`.
- Callback: POST -> 302 to the GET with the merged params; no state ->
  `<base>/api/auth/error?error=state_not_found`; unknown / used / expired
  state -> `state_mismatch`; provider `error` -> `<errorURL>?error=..&error_description=..`;
  `no_code`, `oauth_provider_not_found`, `invalid_code` (token request),
  `unable_to_get_user_info`, `email_not_found`. User: account owner by
  `(providerId, accountId, tenant)` -> update tokens; else email match ->
  link when the provider is trusted or the email verified
  (`requireLocalEmailVerified: false`), else `account_not_linked`; the claim
  hook runs before each account insert (`unable_to_link_account` on refusal);
  else sign-up (gate: 403 `{ message: "signup_disabled" }`). A verified
  provider email marks a matching unverified user verified. Session cookie,
  302 to `newUserURL || callbackURL` for a new user, else `callbackURL`.
- User info: Google = id token claims; Facebook = Graph `/me` +
  `mapFacebookProfileToUser`; generic = id token claims with `sub` + `email`,
  else the userinfo endpoint (`name` / `preferred_username` / given + family).

Tests: `crates/api/tests/session_oauth_sign_in.rs` — 8 Rust-native, against a

## 4. Slice 4 — mobile auth endpoints and JWKS

Source: `packages/auth/src/mobile-auth.ts`, `business/src/mobile-auth/service.ts`,
better-auth `jwt()` plugin. Tests: `packages/auth/__tests__/mobile-auth.test.ts`
→ `crates/api/tests/session_mobile_auth.rs` (23 ported + 1 Rust-native JWKS test).

- `session/jwt.rs`: EdDSA keys in `"Jwk"` (private key stored as better-auth
  writes it: XChaCha20-Poly1305 with SHA-256(secret), hex), `signing_key`,
  `sign_jwt`, `jwks`, `verify_jwt` and `DbJwtVerifier` (local keys, no HTTP).
- `session/mobile.rs`: `POST /api/auth/mobile/token` (grants `password`,

  family revoke on reuse), `GET /api/auth/mobile/callback`,
  `POST /api/auth/mobile/revoke`, `GET /api/auth/jwks`, and the server-only
  `mobile_change_password`.
- Not in this slice: the mobile principal of the `/v1` middleware
  (`resolveMobileWorkspacePrincipal`, member route allowlist, `/v1/me*`) and
  the password-grant rate limit; `LiveAuthDeps` still refuses mobile tokens.

## Decisions

- (slice 4) The better-auth `rateLimit` rule of `/mobile/token` (3 per 10 s) is
  not ported: the Rust auth router has no rate limiter yet (also not for
  sign-in). The TS test of the rule is not ported.
- (slice 4) The ported reuse test moves `rotatedAt` back 31 s before the
  replay: the TS test mocks the service, the real service treats a replay in
  the 30 s grace as INVALID_REFRESH_TOKEN (a concurrent refresh).

- (slice 3) Community has no social providers (as `resolveCredentialForTenant`);
  cloud reads the root `PlatformCredential` per request. The generic provider
  runs on `cloud` / `enterprise`; the license state check of
  `hasEnterpriseFeatures` is not ported (no license service yet).
- (slice 3) Not ported: id-token sign-in (`idToken` body -> 404
  `ID_TOKEN_NOT_SUPPORTED`), the id token signature check (claims are read
  from the token endpoint's response, as `getUserInfo` does), account linking
  for a signed-in user (`link`), `upgradeFacebookAccount` (long-lived token
  exchange), the cross-host callback relay and per-tenant credentials (one
  tenant). Generic discovery runs once at start.

- (slice 2) Server actions the SPA needs become `/rpc` procedures under a new
  top-level key `authActions` (not in the original router); the first is
  `forceChangePassword`. Error codes stay those of the `ChatbotXException`.

- (slice 1) A procedure name that is not in the table, under a known key,
  keeps the P3.5d behaviour (session auth, workspace check when the input has
  a string `workspaceId`, then "not ported"). The original answers 404 "Not
  found" (no match), but the locked `rpc_session_auth.rs` tests call
  placeholder names (`contactsAPIs/list`). Recommended option: keep them green.
- (slice 1) `rpc_router(AuthState)` stays (auth only, no handlers);
  `rpc_router_with(RpcState)` adds the handlers. The server uses the second.
- (slice 1) The input validation error carries no zod `issues` (`data`).
- (slice 1) `findPoll` has no `assertCurrentUserCanAccessChatbot` (no RSC
  layer in the Rust server; the caller checks access).

## Behaviour differences

1. (slice 1) Only the workspace id of the input is validated before the
   handler; the other input fields of an unported procedure are not checked.
2. (slice 1) The owner quota gate (`assertWorkspaceOwnerAccessForMethod`) and
   support-access sessions are not ported (as P3.5d).
