## Slice 1 notes

- `pg_advisory_xact_lock` (`lockFamilyByHash`, `lockFirstWorkspace`, `lockWorkspaceTokens`) and
  row locks (`FOR KEY SHARE`, `FOR NO KEY UPDATE`) are no-ops / plain reads under the one
  SQLite writer (P3.2 rule). The functions stay so callers port 1:1.
- `$onUpdate(updatedAt)`: every UPDATE sets `"updatedAt"` to the wall clock (Drizzle
  `CURRENT_TIMESTAMP`), not to a passed `now`.
- `markOnlineBulk` takes `now: i64` (rule: no SQL `now()`).
- Workspace API token scopes are normalized on read as in the TS (`normalizeWorkspaceApiTokenScopes`):
  a fully valid list is kept as is; otherwise a `WARN` "Dropping unrecognized workspace API token
  scopes" with an `err` field, and the known scopes are kept once each in order.
- `insertWithCredential` is async over `&Db` (one write job; on a unique violation it reads the
  winner on a reader), like the TS `db.transaction` + catch.

## Slice 4 notes

- `leaderboardParticipantRepository.applyChangeInTransaction`: the one-statement upsert
  (`ON CONFLICT ... DO UPDATE ... WHERE NOT banned AND cap AND cooldown`, `xmax = 0`) is a read
  plus insert/update in the caller's write job; a rejected change returns
  `Error::Coded { kind: "LeaderboardChangeRejected" }`. "now" is an input field.
- `pollRepository.upsertVote`: read + insert/update in one write job (same `new` / `changed` /
  `unchanged` outcome; an unchanged re-vote reports the stored `updatedAt`).
- `claimRewards`: the locked sub-select "value before the update" is a read before the update in
  the same write job; `now` is a parameter.
- `IntegrationMetaCatalog` has one row per workspace (`IntegrationMetaCatalog_workspaceId_key`),
  so the decoy connections of the sendable-product ports live in other workspaces.
- Not ported here: `integration/shopify-upsert-product-concurrency.test.ts` tests
  `externalStoreRepository.upsertProduct` (`external-store`, P3.2 range, not in P3.2 section 5).
