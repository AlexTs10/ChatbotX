## Slice 1 notes

- `pg_advisory_xact_lock` (`lockFamilyByHash`, `lockFirstWorkspace`, `lockWorkspaceTokens`) and
  row locks (`FOR KEY SHARE`, `FOR NO KEY UPDATE`) are no-ops / plain reads under the one
  SQLite writer (P3.2 rule). The functions stay so callers port 1:1.
- `$onUpdate(updatedAt)`: every UPDATE sets `"updatedAt"` to the wall clock (Drizzle
  `CURRENT_TIMESTAMP`), not to a passed `now`.
- `markOnlineBulk` takes `now: i64` (rule: no SQL `now()`).
- Workspace API token scopes are normalized on read as in the TS (`normalizeWorkspaceApiTokenScopes`):
  a fully valid list is kept as is; otherwise a `WARN` "Dropping unrecognized workspace API token
  scopes" with an `err` field, and the known scopes are kept once each in order.
- `insertWithCredential` is async over `&Db` (one write job; on a unique violation it reads the
  winner on a reader), like the TS `db.transaction` + catch.

## Slice 4 notes

- `leaderboardParticipantRepository.applyChangeInTransaction`: the one-statement upsert
  (`ON CONFLICT ... DO UPDATE ... WHERE NOT banned AND cap AND cooldown`, `xmax = 0`) is a read
  plus insert/update in the caller's write job; a rejected change returns
  `Error::Coded { kind: "LeaderboardChangeRejected" }`. "now" is an input field.

## Slice 5 notes (message)

- One SQLite file holds every message: the shard fan-out of each method is one query; shard
  selection, shard retry (`withShardRetry`), shard-failure swallowing and `requireCompleteResults`
  shard errors do not exist. The `sinceTime` checks ("sinceTime is required for X in sharded
  repository") and the `createdAt >= sinceTime` filters stay. `listByConversation`, `deleteBySourceId`,
  `patchBySourceId`, `mergeContentAttributesBySourceId` and `findAttachmentById` have no time filter
  in the TS queries (the time only chose shards), so they find rows at any age here.
- `matchesCreatedAt` (whole-millisecond range for Postgres microseconds) = `"createdAt" = ?` on
  integer milliseconds.
- `createOrUpdate*`: the distributed lock is not needed (one writer). Dedup guard read, `ON CONFLICT
  (contactInboxId, sourceId, createdAt) DO NOTHING`, re-read by source id, then by the dedup key
  (`findOnWriteShardBySource`), all in the caller's write job.
- Primary-key collision recovery: a `Message_pkey` unique violation of the first insert retries once
  with `repo::new_id()` and the same stamped `createdAt` (SQLite aborts only the failed statement).
- `jsonb ||` overlay merge = `json_set(COALESCE(col, '{}'), '$."k"', json(v), ...)` (explicit `null`
  kept); `claimContentAttributes` guard `contentAttributes -> key IS NULL` = `json_type(..) IS NULL`;
  `buttonPayloads ? buttonId` = `EXISTS (SELECT 1 FROM json_each(col, '$.richResponse.buttonPayloads')
  WHERE key = ?)`.
- `getSafeSinceTime` floors to the UTC hour (the JS `setMinutes` uses the process zone; servers run UTC).
- Every UPDATE sets `"updatedAt"` (Postgres trigger `update_updated_at_column`, DDL comment).

## Slice 6 notes (whatsapp-call)

- Every UPDATE sets `"updatedAt"` (Drizzle `$onUpdate`); `touchLivenessIfStale` sets it itself.
- `listRecordingsPastRetention` takes `now` (no default clock); `recordedAt < now - retentionDays * 86400000`.
- UNIQUE index names (`WhatsappCall_pendingOutbound_key`, `WhatsappCall_wacid_key`) are resolved inside
  the write job (`DbError::resolve_constraint`), because the job wrapper resolves them only on exit.
- `attachWacid` (behaviour difference, recommended option): the `isNull(wacid)` UPDATE that hits
  `WhatsappCall_wacid_key` counts as "no row updated" (Postgres throws 23505 there, so the TS merge
  path is reachable only in the mock); then the merge runs. The newer row is deleted before the
  older row takes its `attemptId` (`WhatsappCall_attemptId_key` is not deferrable; the TS order
  would violate it).
- `listForWorkspace`: `createdAtCursor` is the ISO millisecond text (`repo::iso`); the cursor is read
  back with `parse_iso` (exact on integer milliseconds).

## Slice 7 notes (pipeline)

- Money (`PipelineItem.value`, activity `fromValue`/`toValue`) is the stored x 10,000 integer in
  every repository input and output (`value` filter amounts, `listStageTotals.totalValue`,
  `dailySeries` / `totalsByActor` sums). The TS returned major units (`float8`); the API layer scales.
- Cursor sort values: timestamps are the ISO millisecond text (`repo::iso`), `value` the 4-digit
  decimal (`12.5000`), `priority` the rank `1`..`3`. Decoding accepts every Postgres
  `timestamptz` text the TS accepts (5-digit years, `BC`, second offsets) and binds unix ms
  (fraction truncated to ms, no offset = UTC); `value` binds x 10,000 (a REAL beyond i64).
  base64url decode skips characters outside the alphabet (Node `Buffer`).
- `JOIN LATERAL` board page = one page query per stage, in stage id order. `DISTINCT ON` =
  `row_number() OVER (PARTITION BY pipelineId ...)`; `array_agg` = `json_group_array` over an
  ordered subquery (`None` for no assignee).
- `fieldValues ->> id` = `CASE json_type(fv, ?) WHEN 'text' THEN fv ->> ? WHEN 'null' THEN NULL
  ELSE fv -> ? END` with the key bound as the JSON path `$."<id>"` (a key holding `"` or `\` reads
  as absent); `? key` = `json_type(fv, ?) IS NOT NULL`; `fv - key` = `json_remove`. `~` = app
  `regexp`; `::numeric` = `CAST(.. AS REAL)` (behaviour difference: number field conditions compare
  as doubles, exact to about 15 significant digits); datetime day = `strftime` of `tz_wall_ms` of
  `unixepoch(stored, 'subsec')`; date day = `substr(stored, 1, 10)`.
- `ilike` = app `ilike()`; `is distinct from` = `IS NOT`; `inArray` = `IN (SELECT value FROM json_each(?))`.
- Row locks (`lockShared`, `lockExclusive`, `lockForUpdate`, `lockFieldsShared`,
  `lockUserIfExists`) are plain reads and `acquirePipelineAdvisoryLock` is a no-op (one writer).
- Every UPDATE sets `"updatedAt"` (`$onUpdate`, also the `upsertMember` conflict update), except
  `stripFieldKeyBatch` (keeps it) and `scrubContactTitles` (activity has no `updatedAt`).
- `fieldConditions` / `fieldTypes` / `activity` are `BTreeMap`s (conditions in key order; the SQL
  is an AND, so the order does not change the result).
- `bind1(text, v)` (`pipeline_item_cursor.rs`): a one-value fragment whose text holds its `?`
  (`Sql::bind` appends the `?`).
