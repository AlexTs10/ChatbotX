## 1. Common contract (all 48 operations)

### 1.1 Auth (`workspaceTokenAuthAPIForScope(scope)`, `apps/builder/src/orpc.ts`)

Order of checks, all before input validation:

1. No `Authorization: Bearer` (and no `?token=`) or an unknown token -> **401**
   `{defined:true, code:"INVALID_CHATBOT_TOKEN", status:401, message:"Invalid or missing workspace API token"}`.
2. Rate limits: 600 / 10 s per client IP before auth, 120 / 10 s per workspace.
3. Read-only token on any POST/PUT/PATCH/DELETE of this unit -> **403**
   `{defined:true, code:"FORBIDDEN", message:"Read-only token cannot perform this operation"}`.
   No P1.8 POST is on `READ_ONLY_TOKEN_ALLOWED_POST_PATHS`. Read-only tokens pass auth on every GET.
4. Scope: `scopes === null` = all scopes; else the operation's scope must be listed, else **403**
   `{defined:true, code:"FORBIDDEN", message:"Token is not authorized for the '<scope>' scope"}`.

Scopes: `media` (dynamicImages), `ecommerce` (ecommerceAnalytics, ecommerceSettings),
`broadcasts` (emailTopics), `analytics` (errorLogs), `integrations` (externalWebhooks),
`automation` (facebookLeadAds, fbComments), `ads` (facebookMarketingMessages).

Covering test: `00-auth.test.ts` (table of all 48 operations: no token, unknown
token, wrong scope, read-only write, read-only read; one read per scope with a
token that has only that scope).

### 1.2 Errors

- Input schema failure (body, query or path) -> **422**
  `{code:"invalidRequestData", status:422, defined:true, data:{issues:[{path,message,…}]}}`.
  Tests compare `code`, `status` and issue `path`s, never zod's text.
- `ChatbotXException` -> its `code` and status (default `systemError`/400). `defined` is
  true when the code is in the route's error map (`commonApiErrors` holds
  `validation`/422, `systemError`/400, `invalidRequestData`/422,
  `INTERNAL_SERVER_ERROR`/500, …), else false. When the exception carries `data`,
  the message gets the data appended: `"<message> (key=value, …)"`
  (`toDisplayMessage`); the `data` itself is dropped (only `STRUCTURED_ERROR_CODES`
  keep it).
- `notFoundException` -> `notFound`/404; `validationException` -> `validation`/422
  (field not exposed).
- An `SdkException` from a channel client (e.g. a Graph 4xx) -> `BAD_REQUEST`, the
  provider status, `defined:false`, message = the provider's message.
- An unmapped error (e.g. a unique-index violation) -> 500 `INTERNAL_SERVER_ERROR`.

### 1.3 Paging (`publicListRequest`)

`page` integer >= 1 (default 1), `perPage` integer 1..50 (default 50); strings are
coerced (`SmartCoercionPlugin`; booleans `"true"/"false"` too). Response
`{data, pageCount}` with `pageCount = ceil(total/perPage)` (0 when empty) unless noted.
Array-of-object query params use bracket notation (`sort[0][id]=name&sort[0][desc]=false`).

### 1.4 Normalization used by this unit

Explicit assertions only (no snapshots). Ids are checked by format
(`^\d{15,20}$`) and by equality with ids the test got earlier; times by
`Date.parse` or by equality with a time the test set. Lists without a documented
order are sorted by id (or by a `sort` the test passes) before compare. Names
used in sort tests start with lowercase letters so that the order is the same
under binary and locale collation.

## 2. dynamicImages (`features/dynamic-images/api/public.ts`, `packages/business/src/dynamic-image/{service,render,qr}.ts`, trigger route `app/dynamic-images/route.ts`)

Resource: `id, name, customFieldId|null, data, enabled, createdAt, updatedAt,
backgroundUrl|null, imageUrl` (no `workspaceId`). `data` = `{width int>0, height
int>0, elements[]}`; each element has `id, x, y, width, height, priority`
(default false) and `type`:
`image` (`imageType` url|avatarUser|customField, `url?`, `customFieldId?`,
`imageStyle` square|circle default square), `qrCode` (`text`, `size` int 64..1024,
`color`, `logoUrl?`), `text` (`text, fontSize, fontFamily` arial|serif|roboto|greatVibes,
`align` left|center|right, `color, bold, italic, uppercase` default false). Stored
and returned with zod defaults applied.
`backgroundUrl` = public storage URL `<storage>/public/space/<ws>/dynamic-images/<id>/background_<ms>.png`.
`imageUrl` = `<broker origin>/dynamic-images?dynamicImageId=<id>&userId={{user_id}}`
(literal braces; parity: `http://app/...`).

Rendering: a static element is a `url` image without `priority`, or a text/QR
element without `{{…}}`. Only the leading run of static elements is baked into
the background (a static element after the first dynamic one is dynamic).
Canvas is rendered at 2x (`RENDER_SCALE`): PNG size = 2·width x 2·height,
transparent where nothing is drawn; images are scaled to fit ("contain"),
centered in their box. A `url` image is fetched with plain `fetch` (no SSRF guard)
at save time. Upload: `image/png`, `public-read`.

## 3. ecommerceAnalytics (`features/ecommerce-analytics/api/public.ts`, `packages/business/src/ecommerce-analytics/service.ts`, `packages/database/src/repositories/order/analytics.ts`)

`get` GET `/v1/ecommerce/analytics`, scope `ecommerce`. Input `from?`, `to?`
(`YYYY-MM-DD` regex, else 422; workspace timezone; `from` defaults to today,
`to` to `from`). Output keys: `currency, otherCurrencyOrders, from, to, timezone,
granularity` (hour when from==to, else day), `lifetime, sales, orders, products`
(`{value, change}`), `series[{key, sales, orders}]` (every hour `YYYY-MM-DDTHH` or
day `YYYY-MM-DD`), `topProducts[{productId|null, name, quantity, sales}]` (≤10 by
sales; lines of deleted products grouped by name), `topVendors[{vendorId|null,
name, sales}]` (≤10, lines with a vendor name only).
Rules: cancelled orders never count; only orders in the store currency
(`payments.currency`) count, the others are counted in `otherCurrencyOrders`;
previous period = same length just before; `change = round1((cur-prev)/prev·100)`,
`0` when both 0, `null` when prev is 0 and cur is not; `lifetime.value` = all
sales ever; `lifetime.change` = percent change of "sales up to the period end"
against "that minus the period's sales". Money rounded per currency.
An inverted or > max range falls back to the default range (not asserted; P1.3
analytics finding). Tests: `03-ecommerce-analytics.test.ts` (day range, hour
range, store currency, workspace timezone, empty store/default day, 422).

## 13. Original behavior the Rust port must match

- Marketing messages: `campaigns.update` of an unknown id is 400 `mmNotFound`
  (get/stop/resume/send 404); `campaigns.delete` of an unknown id is 200 `{id}`;
  `audiences.create` answers 201 `{status:"invalid"}` for a missing grant, Page,
  ToS or a Meta reject, while `uploadMore` throws 400 `mmGrantInvalid` without a
  grant and answers 200 invalid for an unknown id; audience delete refusals are
  400 `systemError`; create/update/liveStatus/statistics call `/debug_token` on
  every call, delete/resume/send only read the stored status; an invalid or
  scope-less `/debug_token` answer and a Graph 190 on send persist
  `status=invalid`; statistics needs no grant without campaigns and checks the
  range before the grant.
- `dynamicImages.create` with a name already used in the workspace -> **500
  `INTERNAL_SERVER_ERROR`** (unique index not mapped; the background file is
  already uploaded and stays orphaned).
- A static `url` image layer (and a QR `logoUrl`) is fetched with plain
  `fetch` at save time, **without the SSRF guard**; only `customField` image
  layers pass `isSsrfUnsafeUrl` (DoH). Tests assert the fetch, not the absence
  of a DoH lookup, so the Rust port may add the guard to `url` layers.
- Rendered PNGs are 2x the canvas size (supersampling), transparent background.
- Every save writes `background_<ms>.png` and deletes the older background
  files; `update` also deletes per-contact renders and clears the cached URLs on
  the **old** `customFieldId`.
- `dynamicImages.update` (PUT) is a full replace (`name` and `data` required).
- `ecommerceSettings`: unknown flow ids give 404 `notFound` "Flow not found"
  (not the 422 "… does not exist." messages); messages of exceptions with `data`
  get `" (key=value)"` appended (`paymentProviderNotConnected`,
  `externalStoreNotConnected`).
- `ecommerceAnalytics.lifetime.change` is the change of "sales up to the period
  end" against "that minus the period's sales" (not against the previous period);
  `change` is 0 when both sides are 0 and null when only the previous is 0.
- `emailTopics.create` answers only `{id}` (201); `update` ignores `folderId`.
- `errorLogs.list` silently ignores `sort`; keyword matches provider labels.
- `externalWebhooks.list` `pageCount` is at least 1 (in-memory paging: empty list
  -> `pageCount: 1`); SSRF refusal is 422 `invalidRequestData` with
  `defined:false` and no `data`; the limit error is 400 `defined:false`.
- `externalWebhooks.create` is idempotent on (event, url) across providers: the
  first provider is kept. A `make` step delivers to every registration of the
  event, `make` and `n8n` alike.
- `facebookLeadAds.delete` of an unknown or foreign id -> 204. `create` subscribes
  the Page before the duplicate check, so a duplicate still calls Graph. The
  subscribe is first tried with the marketing message fields, then retried
  without them.
- `facebookLeadAds.listPages` drops a page whose `debug_token` call fails, and
  reports a page whose auth has no app client id/secret as ineligible without a
  call. Lead ads use `auth.metadata.version`, FB posts use `auth.version`
  (both default `v23.0`).
- `fbComments.create` with an unknown reply flow -> 404 `defined:false` (create
  route map has no `notFound`). `list` without `folderId` lists every folder
  (`includeAllFolders`), `folderId=0` only unfiled. `listPosts` drops a failing
  post type per Page instead of failing the request.
- `fbComments.create`/`update` do not check that `folderId` belongs to the
  workspace (FK only). Not asserted; the Rust port may add the check.
