## 1. Common rules (all 58 operations)

### 1.1 Auth and scope

- Workspace token (`Authorization: Bearer cbx_ws_…`). Middleware order as in
  P1.3 §1.1: token → pre-auth IP limit (600/10 s) → workspace → per-workspace
  limit (120/10 s, 429 `tooManyRequests`) → deletion check → read-only check
  → owner gate → **scope** → idempotency → input validation → handler.
- No / unknown token: **401** `INVALID_CHATBOT_TOKEN`, message
  `Invalid or missing workspace API token`, `defined: true`.
- Scope: `contacts.sendMessage`, `listMessages`, `getMessage` → `inbox`;
  `contacts.sendFlow`, `triggerAutoReply` → `automation`; the other 53 →
  `contacts`. Missing scope: **403** `FORBIDDEN`,
  `Token is not authorized for the '<scope>' scope`. A `contacts` token does
  not open the 5 inbox/automation routes.
- Read-only token: the 20 GETs and `POST /v1/contacts/filter-value-labels`
  (on `READ_ONLY_TOKEN_ALLOWED_POST_PATHS`) pass; the 37 others are **403**
  `FORBIDDEN` `Read-only token cannot perform this operation`.
  `POST /v1/contacts/search` is a read but is NOT on the allow-list → 403.
- Workspace tokens are never member-scoped: full PII, every contact
  (`contactScopeForCaller` → `UNSCOPED`). Mobile-JWT member scoping is out of
  this unit (§6).

### 1.2 Errors

- Body `{ defined, code, status, message, data? }`. Schema rejection: **422**
  `invalidRequestData`, `data.issues[].path`.
- `ChatbotXException` → its code and status; `message` = exception message,
  plus ` (k=v, …)` when the exception carries `data` and the code is not a
  structured one (e.g. `invalidFieldOperation`:
  `This operation cannot be applied to the field (operationNotAllowed). (reason=operationNotAllowed)`, `data` dropped).
- Business validation (`validationException`): **422** `validation`, no `data`.
- Query arrays use bracket notation `key[]=a&key[]=b`; a single plain
  `key=a` is a string and fails an array field with 422 (`expected array`).
- `Idempotency-Key` on writes: replay returns the first response with
  `Idempotent-Replayed: true`; the same key with another body → 422
  `idempotencyKeyReused`.

### 1.3 Contact identifier (`{identifier}` path param)

`parseContactIdentifier` (`packages/business/src/contact/utils.ts`):
- `id:<digits>`, `email:<exact>`, `phone:<exact>`; match is exact and
  case-sensitive on the stored column.
- No `:` or empty value → 404 `notFound` `Invalid identifier format`; other
  prefix → 404 `Invalid identifier format. Use id:, email:, or phone: prefix`;
  `id:` non-digits → 404 `Contact not found`; no row → 404 `Contact not found`.
- Resolution is cached in Redis (`contacts:<ws>:identity:<identifier>`, tag
  `contacts:<id>`); a miss is not cached; delete/update invalidate the tag.
- A contact of another workspace is 404.

### 1.4 Contact resource

`contactResponse` = every `Contact` column (`id, createdAt, updatedAt,
avatar, phoneNumber, email, emailVerified, emailOptIn, firstName, lastName,
fullName (generated), gender, lastReadAt, ref, country, state, city,
location, locale, timezone, subscribedAt, broadcastSubscribedAt, blockedAt,
totalTagged, totalNewTagged, workspaceId`) + `contactCustomFields[]` (raw
rows), `tags[]` (full Tag rows), `contactInboxes[]` (11 columns + full
`inbox`), `conversation` (all columns + `assignedUser`, `assignedInboxTeam`).
Snapshots: `01-crud`, `02-list-search`.

Avatar: `get`, `list`, `search` run `resolveContactAvatars` (public URLs).
A contact with a messenger/instagram inbox and no stored avatar gets
`<appUrl>/media/avatar/<signed token>`; the token is AES-encrypted with a
random IV, so it differs on **every** read. Telegram/webchat contacts keep
`null`. `create`, `upsert` and `findByCustomField` return the stored value
(no resolution). Tests compare the proxy URL by pattern
(`helpers.ts: AVATAR_PROXY`).

### 2.2 List, search, count

- `list` GET `/v1/contacts`, `search` POST `/v1/contacts/search` (deprecated,
  same input in the body): `page` (int ≥ 1), `perPage` (int ≥ 1, capped at 50,
  default 50), `sort` (JSON `[{id,desc}]`, any `Contact` column, applied in
  order; unknown columns dropped; unparsable → ignored; default
  `createdAt desc`; **no id tie-break**; Postgres NULL order: ASC last, DESC
  first), `keyword`, `contactFilter` (JSON string in the query, object or
  string in the body; invalid → 422, unlike the builder), `channels[]`,
  `inboxIds[]`, `integrationWhatsappId`, `integrationMessengerId`,
  `subaction`, `include[]` (`tags|customFields|inboxes|conversation`; omit =
  all; `[]` = none), `withCount` (default true; false → `totalCount 0,
  pageCount 0`). Output `{data, pageCount, totalCount, totalCountCapped}`;
  `pageCount = ceil(total/limit)`; count capped at 10 000.
- Keyword (`buildSmartKeywordWhere`), after trim; JS-lowercased; SQL `ILIKE
  %kw%` (LIKE wildcards escaped):
  - contains `@` → email only;
  - digits only → `id = kw` (if bigint) OR first/last name OR email OR phone;
  - phone-like (`[+\d\s\-()]+`) with ≥ 6 digits → phone ILIKE with spaces,
    dashes, parentheses removed;
  - else first name OR last name, OR an exact `ContactInbox.sourceId = kw`
    (case-sensitive).
  - Never against `fullName` ("Émile Zola" finds nothing), no accent folding
    ("emile" does not find "Émile"), Unicode case folding yes ("ÉMILE"
    finds "Émile"), 1- and 2-character keywords work (no trigram minimum).
    The Rust FTS5 trigram index must not change any of these (fallback for
    < 3 characters needed).
- `count` GET `/v1/contacts/count`: same filters + `countMode`
  (`exact`|`bounded`). With no keyword, filter, audience key and scope it
  returns Σ `InboxContactStat.totalContacts` of the workspace's inboxes (kept
  by a ContactInbox insert trigger: a contact on 2 inboxes counts twice, one
  without inbox not at all). Any filter (even `{operator:"and",conditions:[]}`)
  makes it a real `COUNT`. Output `{total, totalCountCapped}`; bounded adds
  `countCap: 100000`. 503 `countTimeout` on a slow exact count (not tested).
- Tests: `02-list-search.test.ts` (keyword matrix incl. é/ö/ễ/CJK/`%`/`_`,
  order, multi-sort, NULL order, paging, cap 50, include, withCount,
  audience keys, count shortcut vs real count, bounded, filter input).

### 2.3 Contact filter (`contactFilter`)

Shape `{operator:"and"|"or", conditions:[…], timezone?}` (flat, no nested
groups, no condition limit). Field table, operators and SQL semantics: see
`.agents/skills/contact-filter` and `packages/database/src/queries/contact-filter/`.
Rules the tests lock in (`03-filter-matrix.test.ts`, one workspace, five
contacts):

- Text (`fullName`, `email`, `phone`): case-insensitive ILIKE for every
  operator; `ne`/`notContains` also match NULL; `isEmpty` = NULL or `''`.
- Select/multi-select columns (`gender`, `country`, `locale`, `timezone`):
  exact, case-sensitive; list value → IN; `ne` matches NULL; `continent` maps
  `country` (unknown = NULL, `''`, unmapped).
- Booleans: `subscribedToBroadcast`/`blocked` = timestamp IS NOT NULL;
  `emailWasVerified`/`optedInForEmail` = column value; `hasContactInfo`,
  `existingContact` presence (`''` = absent).
- Dates: precision window from the value (day/minute/second), naive values in
  `filter.timezone` (unknown zone → UTC), explicit offset wins; gt = from the
  window end, lte = to the window end, isBetween inclusive of both days.
  A bad value (`11/02/2025`, `2025-02-30`, `2025-13-01`, `yesterday`,
  minutes `1.5`, `abc`) is **not** refused: the condition builds no SQL and
  the list returns the whole workspace (200).
- ContactInbox relations (`currentChannel`, `source`, `inbox`, `language`):
  EXISTS / NOT EXISTS, so negations match contacts without inboxes; `isEmpty`
  = no inbox (language: no non-empty language). `lastInteraction`/`lastSeen`/
  `lastSent` use MAX over inboxes; `interactedInLast24h`, `unreplied`,
  `consecutiveAiFailures`.
- Conversation relations (`archived`, `followUp`,
  `conversationTransferredToHuman`, `unread`, `conversationAssigned` with
  `u_<userId>`): `eq false`/`isEmpty` = NOT EXISTS.
- `tags` (any of / none of / no tags), `subscribedToDripCampaign`.
- Custom fields: EXISTS on `ContactCustomField`; negations = NOT EXISTS of
  the positive; text `eq` case-sensitive, `contains`/`startsWith` ILIKE;
  number compared numerically (`10.0 = 10`), `contains` textual; date
  day-compare; datetime instant window in `filter.timezone`; boolean literal
  sets (`yes` = `true`); `longText` only eq/ne/isEmpty/isNotEmpty; unknown
  field id → no match. Wrong operator for the value type → 422.
- Bot fields: uncorrelated → all contacts or none.
- `keyword` AND filter AND audience keys.

## 5. Original behavior the Rust port must match (surprises)

- `create`/`upsert` responses keep the stored avatar (`null`); `get`/`list`
  return a media proxy URL for messenger/instagram contacts without avatar,
  a new token on every read.
- `create` requires `email` and `gender` keys even for channels that do not
  use them (`email: ""` is accepted).
- An invalid contactFilter date / minutes value is silently dropped and the
  list answers the whole workspace (no 422).
- Custom field `date` values are stored as `YYYY-MM-DDT00:00:00Z`; a non-ISO
  date is answered 204 and not stored; a missing operand in
  `applyCustomFieldOperations` is a 400 `invalidFieldOperation`, not a 422.
- Import upload path keeps the declared extension case (`import_<id>.CSV`).
- Export `sys:source` is always empty; an unknown `tag:<id>` column says `No`.
- `resolveFilterValueLabels` (public) only knows `tags`.
- `analytics:dashboard contact:created` from `create`/`upsert` carries the
  ContactInbox id as `contactId` (not observable through `contacts.*`).
- `count` without filters is the InboxContactStat sum (double counts a
  contact on two inboxes, ignores a contact without inbox); an empty filter
  turns it into a real count.
- Keyword search never matches the full name and never folds accents; it does
  fold case for non-ASCII letters and works for 1–2 characters.
- `sort` has no id tie-break; NULLs last on ASC, first on DESC.
- Single query value for an array param is a 422 (bracket notation needed).
- `unsubscribeSequences` (single) ignores unknown sequence ids (204), while
  `bulkUnsubscribeSequences` and `subscribeSequences` 404.
- `addTags` silently ignores unknown / foreign tag ids.
- `invalidFieldOperation` message repeats the reason: `… (reason) (reason=reason)`.
- `POST /v1/contacts/search` is refused for a read-only token, while
  `POST /v1/contacts/filter-value-labels` is allowed.
- Import never updates existing contacts; duplicates are failures without
  an error sample.
- Export: formula guard prefixes `'` to phone numbers starting with `+`.

## 6. Not tested black-box (with reason)

- Mobile-JWT member principals (`x-workspace-id`): member contact scope
  (`onlyAssignedContacts`, teams), PII masking, `assertMemberMayStartFlow`.
  Shared middleware; needs the mobile auth unit.
- 503 `countTimeout` (needs a statement timeout on a huge workspace), the
  10 000 list-count cap, `countMode=bounded` capping (needs > 100 000 rows).
- 409 `contactImportAlreadyRunning`: the worker finishes small imports in
  milliseconds, so a pending import cannot be held deterministically.
- Import of more than 100 000 rows, a file > 20 MB in the storage, XLSX (not
  accepted for contacts).
- `refreshProfile` `updated` / `unavailable`: needs a channel integration
  with a token and a scripted Graph/Telegram profile answer (channel units).
- `sendMessage` on real channels (Messenger, WhatsApp, Telegram …),
  products, media and file uploads (`multipart`): channel units; only
  webchat text is sent here.
- `bulkTagByStats` broadcast and commentAutomation positive paths (need
  broadcast send / comment automation rows; the sequenceStep path covers the
  job); trigger/automation and webhook side effects of tag and field events
  (webhooks fire only in channel context).
- Activity-backed filter fields (`executedFlow`, `keywordsReceived`, email
  events, `clickedAd`), commerce, comments, pipelines, coupons, leaderboard,
  CTWA retarget, questionnaires: need their own domain rows; covered by the
  owning units. `CONTACT_ACTIVITY_FILTERS_ENABLED` gates the activity fields.
- Upsert with an `http(s)` avatar (downloads the image: outbound call and
  image optimization).
- Audit records (no public read), quota counters (cloud editions), cache
  expiry.
