## Decisions

- `Call` keeps its four fields: the locked fixture builds `Call {..}` and
  `Principal {..}` by struct literal. `call.token_id()` reads the token id of
  the running `dispatch_as` (a tokio task-local, the `AsyncLocalStorage`
  pattern of the original). `dispatch` (no principal) gives `None`.
  Accepted by the orchestrator.
- `ApiState::new(db, app_url)`: every service off (no realtime, kv, jobs;
  audit records dropped; bus without subscribers). `with_jobs` also turns on
  the audit writer. The server wires a `JobStore` on the app database, the
  `Kv`, and the `Realtime` producer when the gateway is on.
- The in-process bus (`events::EventBus`) is a list of subscribers that
  `publish` awaits in order; a subscriber error is logged ("Failed to emit
  event: <type>") and the next subscriber still runs (`emitToAllEmitters`,
  `Promise.allSettled`). Events are typed: `Event::Trigger(TriggerEvent)`
  (the `BaseEventEmitter.emit` shape: type, workspace id, contact id,
  metadata) and `Event::Bus { event_type, payload }` (for the durable buses).
- Trigger / webhook emitters are bus subscribers (`QueueEmitter::trigger` /
  `::webhook`): they queue `evaluate-triggers` / `evaluate-webhooks` jobs.
  The workers that evaluate them (and start flows) are out of scope.
  `isWorkerContext` (skip emits from the worker) is not ported: the API is
  never a worker context.
- The active-condition cache keeps only the RAM layer (5 s TTL) of
  `BaseCache`; the Redis layer (1 h) shared state between processes, and the
  lean build is one process.
- The audit writer enqueues `sendAuditLog` on the `default` queue with job id
  `audit-log-<id>`, as the original. The handler (`send-audit-log.ts`) does
  nothing on the community edition.
- `dispatchAuditRecord` / the global recorder registry is not ported: the
  writer is injected through `ApiState`.
