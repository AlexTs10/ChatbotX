## 1. Public behavior

### 1.1 Constants and types
- `DEFAULT_MIME_TYPE = "application/octet-stream"`.
- `UploadedFile { name: string; mimeType: string; originPath: string; size: number; fileType: "image"|"video"|"audio"|"file"; width?: number; height?: number }`.
- `ChannelMediaLocation { channel, workspaceId, integrationId }` (all strings).
- `UploadValidationError extends Error`, `name = "UploadValidationError"`. Meaning: caller-fault failure (oversize, bad status, too many redirects, SSRF reject). Callers use `instanceof` to choose a 4xx path versus a 5xx path.
- `FileWithPreview = File & { preview: string }` (browser only).
- `createPresignedUploadRequest`: array of `{ type?: string (trim, min 1), subType?: string (trim, min 1), path: string (trim,min1), name: string (trim,min1), mimeType: string (trim,min1) }`.

### 1.2 Key and prefix formats (helper.ts)
- `getDatePrefix()` = UTC date of "now", `YYYY/MM/DD` (`toISOString().split("T")[0]` with `-` -> `/`). Uses the system clock at call time.
- `getStoragePrefix(workspaceId)` = `public/ws/{workspaceId}/{YYYY/MM/DD}`.
- `getChannelMediaPrefix({channel, workspaceId, integrationId})` = `public/{channel}/{workspaceId}/{integrationId}/{YYYY/MM/DD}`. Channel is first so one lifecycle rule can target one channel. Objects are uploaded `public-read`.
- `getMirroredChannelMediaPrefix(loc)` = `workspace/{channel}/{workspaceId}/{integrationId}/{YYYY/MM/DD}` (private root, same layout).
- No validation, no escaping of the inputs.
- `pathJoin(...parts)` = `parts.join("/")` then every run of one or more `/` collapsed to a single `/`. NOTE: this also collapses `//` inside `https://` and does not trim leading or trailing `/`.
- `guessFileTypeFromMimeType(mime)`: first segment before `/` (`mime.split("/")[0]`): `image`->`image`, `video`->`video`, `audio`->`audio`, anything else (including `""`, no slash, uppercase `IMAGE/PNG`) -> `file`. Case sensitive.

### 1.3 MIME rules (mime-type.ts)
Alias table (exact, lower-case keys): `image/jpg` -> `image/jpeg`, `image/pjpeg` -> `image/jpeg`, `image/x-png` -> `image/png`.
`normalizeMimeType(s)`: find first `;`. base = text before it (or all), `trim()`, lower-case. params = text from the `;` on (untouched, including the `;` and any spaces, not trimmed, not lower-cased). Result = `alias(base) ?? base` + params. Unknown types pass through (lower-cased and trimmed). Empty string stays empty.
Reason: Meta (WhatsApp error 131053) rejects `image/jpg`.
Where it is applied: `putObject` (when `ContentType` is present, always last, overriding the caller), `createUpload` (when `contentType` given), `uploadFile`, `uploadFileFromUrl`.

### 1.4 Image dimensions (`getImageDimensions(mimeType, buffer)`)
Returns `{ mimeType, fileType: guess(mimeType) }` plus, only if `mimeType.startsWith("image/")`: try `image-size` on the bytes; success sets `width`, `height` (the library mime is NOT used). On failure (any throw): log warn `"Unable to retrieve image dimensions"` (child logger `uploader`), then force `fileType = "file"` and `mimeType = "application/octet-stream"` in the RESULT (the stored object keeps its original ContentType). Non-image types: no probe, no width/height.
Formats the JS lib supports (the Rust crate should cover the same set as far as practical): bmp, cur, dds, gif, heic, heif, icns, ico, j2c, jp2, jpeg, jxl, ktx, png, pnm, psd, svg, tga, tiff, webp, avif.

### 1.5 `buildCopySource(sourcePath, bucket, endpoint?)` (copy-source.ts)
- Each `/`-separated segment of `sourcePath` is `encodeURIComponent`-ed and re-joined by `/`. `encodeURIComponent` leaves `A-Z a-z 0-9 - _ . ! ~ * ' ( )` unescaped and escapes everything else, UTF-8 percent-encoded with upper-case hex. (`a b/c#d.png` -> `a%20b/c%23d.png`.)
- If `endpoint` is set: `new URL(endpoint).pathname`, strip leading and trailing `/` runs. A non-empty result becomes prefix `"{endpointPath}/"`. An invalid endpoint throws `TypeError` (URL parse). `new URL` also percent-encodes the path.
- Output: `{prefix}{bucket}/{encodedSource}`. Reason: the copy source is a header, so the endpoint path (e.g. an R2 endpoint that already contains the bucket) must be replicated by hand.

### 1.6 Bounded fetch (bounded-fetch.ts)
`readBodyWithLimit(response, maxBytes, onLimitExceeded: (maxBytes) => Error): Promise<Buffer>`
- If `response.body` is null/absent: read `arrayBuffer()` whole; if `byteLength > maxBytes` throw `onLimitExceeded(maxBytes)`; else return it. (A `204` empty response returns an empty buffer.)
- Else read the stream chunk by chunk with a running total. As soon as `total > maxBytes` (strictly greater; exactly `maxBytes` is allowed): `reader.cancel()` then throw `onLimitExceeded(maxBytes)`. Empty/undefined chunks are skipped. Returns the concatenation. A lying or missing `content-length` is irrelevant here (header never read).
- The thrown error is exactly the value the callback returned.

`fetchFollowingSafeRedirects({ errors, fetchImpl(url) -> Response, maxRedirectHops = 5, redirectsLeft = maxRedirectHops, url, validateUrl(url) -> Promise<void> }) -> { finalUrl, response }`
Algorithm per hop:
1. `await validateUrl(url)` (rejection propagates, no fetch is made).
2. `response = await fetchImpl(url)`.
3. If `status < 300 || status >= 400` return `{ finalUrl: url, response }`. (So 304 and any 3xx is treated as a redirect; no status whitelist.)
4. If `redirectsLeft <= 0` throw `errors.tooManyRedirects()` (this check comes BEFORE the Location check).
5. `location = headers.get("location")`; if absent/empty throw `errors.noLocationHeader()`.
6. `redirectUrl = new URL(location, url).href` (relative resolution; the result is normalized, e.g. `https://example.com/b`). On a parse error throw `errors.invalidRedirectLocation(location, cause)`.
7. Recurse with `redirectsLeft - 1`.
Effect: with default 5 hops, 5 redirects are followed and the 6th redirect response throws; `validateUrl` runs 6 times (hop0..hop5) and `fetchImpl` 6 times. With `maxRedirectHops: 2`: 3 fetches then throw.
`SafeRedirectErrors = { invalidRedirectLocation(location, cause), noLocationHeader(), tooManyRedirects() }`, each returns an `Error`.
The response body of an intermediate redirect response is not consumed or cancelled.

### 1.7 `uploadFileFromUrl(url, path, acl = "public-read", maxBytes?, validateUrl?, signal?) -> UploadedFile` (upload.ts, the exported one)
1. Download:
   - If `validateUrl` is given: `fetchFollowingSafeRedirects` with `fetchImpl = (u) => fetch(u, { redirect: "manual", signal })`, default hop limit 5, errors mapped to `UploadValidationError` with messages:
     - too many: `"Too many redirects while downloading file"`
     - no location: `"Redirect response has no Location header"`
     - invalid location: `` `Redirect response has an invalid Location header: ${location}` ``
     `finalUrl` = last URL.
   - Else (no validator): single `fetch(url, { redirect: "follow", signal })`; `finalUrl = url`. No SSRF validation at all, the platform follows redirects itself (callers that need safety must pass `validateUrl`).
   - `signal` abort: fetch rejects (AbortError) and the error is NOT converted to `UploadValidationError`. Network errors also propagate raw.
2. `!response.ok` (status outside 200-299, including a final 3xx in follow mode) -> `UploadValidationError("Failed to download file: {status}")`.
3. `mimeType = normalizeMimeType((content-type header || DEFAULT_MIME_TYPE).split(";")[0])`. Missing OR empty header -> `application/octet-stream`. Params are cut before normalization.
4. `headerLength = parseInt(content-length ?? "0", 10)` (NaN when not numeric). If `maxBytes !== undefined && headerLength > maxBytes` -> `UploadValidationError("File exceeds the maximum allowed size of {maxBytes} bytes")` (early reject; NaN never rejects; the body is not read).
5. `name`: starts as `createId()`. Parse `finalUrl`; `last = pathname.split("/").pop()`; if non-empty `name = decodeURIComponent(last)` (query string and fragment are not part of the pathname). If parsing or decoding throws (invalid URL, malformed `%`), log `warn({ err }, "uploadFileFromUrl: invalid URL")` (logger `filesystem:upload`) and keep the generated id. A path ending in `/` gives the generated id.
6. Body: if `maxBytes === undefined` read the whole body via `arrayBuffer()` (NO limit); else `readBodyWithLimit(response, maxBytes, limit -> UploadValidationError("File exceeds the maximum allowed size of {limit} bytes"))`.
7. `size = buffer.byteLength` (the real byte count; the header is only an early-reject hint).
8. `uploader.putObject(path, buffer, { ACL: acl, ContentType: mimeType, ContentLength: size }, signal)` (4th arg is the abort signal or `undefined`). `putObject` normalizes ContentType again.
9. `getImageDimensions(mimeType, buffer)` (section 1.4).
10. Returns `{ name, originPath: path, size, ...dimensions }` (dimensions spread last, so a failed image probe overrides `mimeType` to octet-stream and `fileType` to `file`).
Errors from `putObject` (storage outage) propagate unchanged (not `UploadValidationError`).

### 1.8 `uploadFile(file, path, acl = "public-read") -> UploadedFile`
Read bytes; `mimeType = normalizeMimeType(file.type)` (`""` stays `""`, DEFAULT is NOT applied); `putObject(path, bytes, { ACL: acl, ContentLength: file.size, ContentType: mimeType })`; then `getImageDimensions`. Returns `{ name: file.name, originPath: path, size: file.size, ...dims }`.

### 1.9 `uploadMultipleFiles(files, prefix, acl = "public-read")`
`Promise.all` (parallel, fail-fast, no cleanup of those already uploaded) of `uploadFile(file, pathJoin(prefix, createId()), acl)`. Key = prefix + random id, with no extension. Result order = input order.

### 1.10 `Uploader` (uploader.ts) — all use `S3_BUCKET` and the single shared client
Construction: `S3Client({ endpoint: S3_ENDPOINT, region: S3_REGION, forcePathStyle: Boolean(S3_ENDPOINT), credentials: {accessKeyId, secretAccessKey} only when BOTH are set, else undefined (default AWS provider chain) })`.
- `putObject(path, body: string|Uint8Array|Buffer|Readable, options?: PutObjectCommandInput partial, abortSignal?)`: `PutObject{ Bucket, Key: path, Body, ...options, ContentType: normalizeMimeType(options.ContentType) if present }`. Returns the SDK output. Abort signal passed as send option.
- `getPresignedUpload(path) -> string`: aws4fetch SigV4 query-signed `PUT` of `` `${S3_ENDPOINT}/${S3_BUCKET}/${path}?X-Amz-Expires=300` `` (fixed 5 min). service `s3`, region `S3_REGION`, credentials `S3_ACCESS_KEY_ID ?? ""` / `S3_SECRET_ACCESS_KEY ?? ""`. The signed URL (`X-Amz-Algorithm`, `X-Amz-Credential`, `X-Amz-Date`, `X-Amz-Expires=300`, `X-Amz-SignedHeaders=host`, `X-Amz-Signature`) is returned. Path-style only. No content type or size is signed. If `S3_ENDPOINT` is unset the URL starts with the string `"undefined/"` (latent bug; Rust must return an error instead).
- `getPresignedDownload(path, expiresInSeconds = 3600) -> string`: same as above with method `GET` and `X-Amz-Expires={expiresInSeconds}`. Callers pass `300` (5 min) for exports/recordings, default 1h for others. No `response-content-disposition` is added. S3 itself caps expiry at 7 days; the code does not clamp or validate.
- `headObject(path)`: `HeadObject{Bucket, Key}`, returns SDK output (callers read `ContentLength`). Missing object -> SDK throws (`NotFound`).
- `getObject(path) -> Buffer`: `GetObject`; no `Body` -> `Error("No body found for object: {path}")`; collects the whole stream (no limit).
- `getObjectStream(path) -> { stream, contentLength? }`: same error when no Body; `contentLength = response.ContentLength`.
- `copyObject(src, dst)`: `CopyObject{ Bucket, Key: dst, CopySource: buildCopySource(src, S3_BUCKET, S3_ENDPOINT) }`. No ACL and no metadata directive (S3 default COPY directive keeps metadata; the ACL is NOT copied, so a public-read source yields a private copy unless the store/bucket policy makes it public).
- `deleteObject(path)`: `DeleteObject{Bucket, Key}`. S3 delete of a missing key succeeds (idempotent).
- `listObjects(prefix, options = {})`: `ListObjectsV2{ ...options, Bucket, Prefix: prefix }`; caller uses `ContinuationToken`; result `Contents[].Key`, `IsTruncated`, `NextContinuationToken`. Page size 1000 (S3 default). Prefix is a raw string prefix (not path-segment aware).
- Singleton: `Uploader.getInstance()` / exported const `uploader`. `accessKeyId`, `secretAccessKey` return `""` when unset; `endpoint`, `region`, `client`, `bucketName` getters.

### 1.11 Streaming upload (node-upload.ts, `./node-upload`)
`createUpload(path, { contentType? }) -> { stream: PassThrough, done: Promise<void> }`: lib-storage `Upload` (multipart, default 5 MiB parts, queue size 4, `leavePartsOnError = false`) on `uploader.client`/`bucketName`, `Key: path`, `Body: stream`, `ContentType: normalizeMimeType(contentType)` when given. No ACL. `done` resolves to `undefined` when the upload completes, rejects on failure.
(The old `uploadFileFromUrl` in this file is dead code, see 6.)

### 1.12 `toUploadWriter({ stream, done }) -> UploadWriter` (upload-writer.ts, `./upload-writer`)
`UploadWriter { write(chunk: string): Promise<void>; bytesWritten(): number; finish(): Promise<void>; abort(): Promise<void> }`.
- On creation: `done.catch(e => { failure = {error: e}; rejectPendingWrite?.(e) })` (the failure is latched).
- `write(chunk)`: if a failure is latched reject immediately with that error and do NOT touch the stream. Else register the pending reject, `stream.write(chunk, cb)`; the promise resolves in the write callback (so it waits for backpressure/consumption). On callback error reject; on success add `Buffer.byteLength(chunk)` (UTF-8 bytes) to `bytesWritten` and resolve. Rejected writes are never counted. Callers must await writes one at a time (at most one pending).
- `bytesWritten()`: running UTF-8 byte total of accepted writes.
- `finish()`: `stream.end()` then `await done` (surfaces the upload failure).
- `abort()`: `stream.destroy()` then `await done.catch(() => undefined)` (always resolves, `undefined`).
- Used by exporters for CSV with `contentType "text/csv; charset=utf-8"`; the exporter writes a UTF-8 BOM itself.

## 2. Side effects

S3 operations (all against bucket `S3_BUCKET`, path-style when `S3_ENDPOINT` is set):
- `PutObject` (putObject, uploadFile, uploadFileFromUrl, via `uploader`), params: Key, Body, ACL (`public-read` default, or `private`), ContentType (normalized), ContentLength, CacheControl/ContentDisposition when the caller passes them.
- Multipart `CreateMultipartUpload`/`UploadPart`/`CompleteMultipartUpload`/`AbortMultipartUpload` (lib-storage, `createUpload`), params: Key, ContentType.
- `HeadObject`, `GetObject`, `CopyObject` (CopySource header per 1.5), `DeleteObject`, `ListObjectsV2` (Prefix, ContinuationToken).
- Presigning is local (no network): SigV4 query signing.

Outbound HTTP (only `uploadFileFromUrl`): one GET per hop to the user-supplied URL. With `validateUrl`: `redirect: manual`, up to 6 requests, `validateUrl(url)` before each. Without: `redirect: follow` (platform default, up to 20 hops, no validation). No custom headers, no User-Agent, no timeout inside the module (the caller supplies `AbortSignal.timeout(...)`; e.g. outbound-media uses its own `DOWNLOAD_TIMEOUT_MS`, channel-post uses an AbortController).

Logs (pino child loggers from `@chatbotx.io/logger`):
- logger `uploader`, warn: `"Unable to retrieve image dimensions"` with the error as first arg (on probe failure).
- logger `filesystem:upload`, warn: `{ err }`, `"uploadFileFromUrl: invalid URL"` (on filename derivation failure).
- (dead) node-upload `uploadFileFromUrl`: `console.error("error", error)`.
No other logging, no metrics.

## 6. Items that cannot map 1:1 (with proposals; no test is dropped)

1. Fake timers / `new Date()` (tests 9, 10): Rust has no global fake clock. Proposal: `_at(date)` variants (above). Assertions unchanged.
2. `globalThis.fetch` monkey-patching (27-33): proposal `HttpFetcher` trait injected through an options struct: `upload_file_from_url(deps: &UploadDeps, url, path, opts: UploadFromUrlOptions)`; `UploadDeps { fetcher: Arc<dyn HttpFetcher>, putter: Arc<dyn ObjectPutter> }`. `Uploader::upload_file_from_url(...)` convenience wrapper builds deps from the real store and `ReqwestFetcher`.
3. `AbortSignal` (test 30 and all callers): use `tokio_util::sync::CancellationToken` (callers with timeouts use `tokio::time::timeout` + token). The "signal is forwarded" assert becomes "same token observed".
4. `instanceof UploadValidationError` (test 27): Rust error enum `FilesError::UploadValidation(String)` and test with `matches!`. `Display` of the variant = the message (tests 32, 33 assert message text via `to_string().contains(...)`; the JS name `UploadValidationError` is not part of the Rust text). Business callers need `err.is_upload_validation()` (or `matches!`).
5. `Response`/`ReadableStream`/`Buffer`: replaced by `HttpResponse`/`Body`/`Bytes`. Test 4's duck-typed Response becomes `Body::Buffered`.
6. Backpressure semantics of Node `PassThrough` (tests 34-40): the Rust writer is built over `tokio::sync::mpsc` (capacity 1 to mimic `highWaterMark: 1`) feeding the multipart uploader task. `stream.writableEnded`/`destroyed` become `UploadSink` state flags (`is_closed()`, `is_destroyed()`) exposed on the fake sink or on the writer for tests. `write(chunk: string)` becomes `write(&mut self, chunk: &str)` and counts `chunk.len()` (Rust `str::len` is UTF-8 bytes, so BOM = 3 bytes, `ễ` = 3 bytes, same as `Buffer.byteLength`).
7. `createUpload` over lib-storage: object_store gives `ObjectStore::put_multipart` -> `MultipartUpload` (parts are written with `put_part`, `complete`, `abort`) and `WriteMultipart` helper. `done` = the join handle of a task that drains the mpsc into `WriteMultipart`, abort on error (`leavePartsOnError=false` equivalent: call `abort()`). LocalFileSystem multipart writes to a temp file and renames at `complete` (good). `ContentType` goes into `Attributes` (`Attribute::ContentType`).
8. `ACL` (`public-read`/`private`): `object_store` has no ACL option on `put` for LocalFileSystem and no first-class one for S3. Proposal: keep `acl` in `PutOptions` for API parity; the local backend ignores it. For S3 either set the header through object_store's `Attribute::Metadata` is NOT equivalent (that is `x-amz-meta-*`), so for S3 the ACL would need a bucket policy for `public/` keys (the key layout already separates public vs private: `public/...` vs `workspace/...`) or a custom `reqwest`-signed PUT. Flag for decision (see doubts). `CacheControl` and `ContentDisposition` map to `Attribute::CacheControl` / `Attribute::ContentDisposition`.
9. Presigned URLs: `object_store::signer::Signer` is implemented only by `AmazonS3` (and GCS/Azure), NOT by `LocalFileSystem`. Proposal: `Uploader::presigned_upload(path)`/`presigned_download(path, expires)` use `AmazonS3::signed_url(Method::PUT/GET, &Path, Duration)` for the S3 backend (SigV4 query signing; expiry 300 s / 3600 s default, the same as before). The local backend needs a different design: an app-served URL signed by HMAC (`/files/{token}`, token = HMAC(path, method, exp)); the P3 route units (builder `presigned-upload`, `media/attachment/[token]`) would serve it. Without a server the local backend can return a `file://` URL for GET only. Tests for presigning do not exist in the frozen set; add Rust tests for the S3 case (URL has `X-Amz-Expires=300`, host-only signed header, path-style `{endpoint}/{bucket}/{key}`) and the local HMAC case.
10. `copyObject` / `buildCopySource`: `object_store::copy` builds its own `x-amz-copy-source` (it includes the bucket and handles encoding itself, and honors the endpoint path through its own URL config). `build_copy_source` is still ported as a pure function and tested (tests 11-15), but the Rust `Uploader::copy_object` does not call it for the S3 backend unless a raw `CopyObject` request is used. Decide if the helper stays only for parity (see doubts). Rust impl of `encodeURIComponent`: percent-encode every byte except `A-Za-z0-9-_.!~*'()` using `percent_encoding::utf8_percent_encode` with a custom `AsciiSet` (`NON_ALPHANUMERIC.remove(b'-').remove(b'_')...`). Endpoint path: `url::Url::parse(endpoint)?.path().trim_matches('/')`. JS throws `TypeError` for an invalid endpoint -> return `Err(FilesError::InvalidEndpoint)` (so the fn returns `Result<String, _>`; tests use `.unwrap()`).
11. Prefix semantics: `ListObjectsV2` prefix is a raw string prefix; `object_store::list(Some(&Path))` is segment-based (prefix `a/b` will not match `a/bc/x`) and does not expose continuation tokens (it paginates internally and returns a stream). Proposal: `list_objects(prefix) -> Vec<String>` listing from the longest directory part of the prefix and filtering `key.starts_with(prefix)`. The two callers (`dynamic-image`, `template-staged-cleanup`) loop on `ContinuationToken`; in Rust they get the full list in one call, so the loops simplify (the `MAX_LIST_PAGES` guard becomes a max-keys guard, noted for the P3 unit).
12. Keys that are not valid `object_store::path::Path` values: `Path::parse` rejects empty segments (`a//b`), and some characters; `Path::from("...")` percent-encodes them, which would change the stored name vs S3 semantics. Proposal: `fn to_path(key: &str) -> Result<Path, FilesError>` using `Path::parse` (strict) so a bad key is a clear error, with a documented list. Needs a decision on user-supplied filenames inside keys (e.g. `uploadFile` with path built by callers). Also reject `..` (path traversal) for the local backend. Leading `/` in keys: S3 would keep an empty first segment; Rust rejects/strips it. Note `pathJoin` always collapses `//`, so keys built with it are safe.
13. `parseInt(content-length)` quirks: `parseInt("12abc") == 12`, `"abc"` = NaN (no reject), negative parses negative. Rust: port with a small helper that mimics `parseInt` prefix parsing (optional sign then digits; no digits -> `None` = never rejects). A header absent -> 0.
14. `decodeURIComponent` + `new URL(finalUrl).pathname`: Rust `url::Url` + `percent_encoding::percent_decode_str(...).decode_utf8()` (error on invalid UTF-8/malformed -> fall back to generated id and warn, matching the JS catch). Note WHATWG URL parsing normalizes the path (dot segments) the same in both.
15. `new URL(location, base).href`: `url::Url::parse(base)?.join(location)?.to_string()`. Both are WHATWG. `Response.redirect` normalizing `https://example.com/b` is used by test 5 (expected `finalUrl` equals the same string).
16. `createId()` comes from `@chatbotx.io/utils` (another unit). The Rust crate needs a dependency on the utils/ids crate (id generator) or an injected `IdGen` (`fn() -> String`). For tests only the length/presence matters (no frozen test asserts the name).
17. `image-size`: Rust `imagesize` crate (header-only, fast) covers jpeg/png/gif/webp/bmp/heic/avif/svg-ish formats; SVG is NOT supported by `imagesize` (image-size supports it). Proposal: `imagesize` for raster plus a tiny SVG viewBox/width/height parser, or the `svg` handling via `usvg` if already in the workspace. Behavior on failure stays the same (force `file` and octet-stream).
18. `FileWithPreview` (browser.ts) and the `File` input of `uploadFile`/`uploadMultipleFiles`: JS DOM/web-platform type. Rust version takes `struct InputFile { name: String, mime_type: String, bytes: Bytes }`. `FileWithPreview` has no Rust equivalent (UI only) and is skipped, as a documented note, not a dropped test (no test covers it).
19. `getObject`/`getObjectStream` return a Node `Readable`: Rust returns `Bytes` (`get_object`) and `ObjectStream { stream: BoxStream<Result<Bytes,_>>, content_length: Option<u64> }` (`get_object_stream`). Callers in P3 units adapt (`AsyncRead` conversion via `StreamReader` if needed).
20. `S3Client` auto-credentials chain vs `object_store`: `AmazonS3Builder::from_env()`-like handling; object_store also supports the instance-metadata/credential chain only partially (no shared-config profile files). Flag in doubts.
21. node-upload.ts `uploadFileFromUrl` is dead and duplicates (older, unbounded) logic: propose NOT to port it (no caller, no test). This is not a test drop. If the lead wants it, port as a thin alias to the bounded version.
22. `keys.ts` (t3-env validation at import): Rust `FilesConfig::from_env()` returning `Result` (validation: region and bucket required unless backend is local; endpoint must parse as URL). `SKIP_ENV_CHECK` becomes: construct `FilesConfig` manually in tests.
23. Singleton `uploader`: Rust `Uploader` is built once at startup and shared as `Arc<Uploader>` through app state (no global static; `OnceLock` helper optional).

## 9. Doubts / decisions needed
1. ACL on S3 (`public-read`) is not expressible with `object_store`. Choose: bucket policy on `public/*` (recommended; `getStoragePrefix`, `getChannelMediaPrefix` already put public objects under `public/`), or a custom PUT. Local backend: public files must be served by the app (a static route for `public/`).
2. Presigned URLs for the local backend (no signer in object_store): HMAC-signed app URLs need a route in P3 builder units. Confirm.
3. Backend selection variable names (`FILES_BACKEND`, `FILES_LOCAL_ROOT`) are new; confirm or choose auto-detect from `S3_BUCKET`.
4. `buildCopySource` has no use in the `object_store` copy path (it builds its own header). Keep as parity-only pure function (needed by frozen tests 11-15) or add a raw S3 copy. Related: S3 copy does not carry the ACL (same as the JS).
5. `listObjects` loses `ContinuationToken` paging; callers' loops need a small rewrite in P3.
6. Key validity (`Path::parse`) vs arbitrary user filenames in keys. Need a rule (reject or percent-encode) so local and S3 backends behave the same.
7. Exact JS `encodeURIComponent` behavior and `parseInt` quirks must be reproduced (listed in 6.10, 6.13). Frozen tests only cover the `%20` and `%23` cases.
8. Unverified: whether the non-filesystem integrations (`telegram`, `zalo`, `messenger`...) import `guessFileTypeFromMimeType` from this package or from `@chatbotx.io/sdk`; the grep matched the name only (zalo and others are listed with the package import lines, but check before wiring).
9. `createId()` dependency (utils unit) and the `image-size` SVG support gap (6.17).
10. `uploadFile` with empty `file.type` stores `ContentType: ""` and returns `mimeType: ""` and `fileType: "file"` (DEFAULT not applied); `uploadFileFromUrl` applies the default. Port as is (inconsistent but behavior-preserving); confirm.
11. Test 35 uses a multi-byte string; the Rust `str::len` gives the same UTF-8 byte count; in the Rust port the fixture string must be copied exactly (BOM `\u{FEFF}` then `a\n`, then `Nguyễn\n`, in NFC).
12. The test named "past hop 6" actually means 6 requests then fail (1 initial + 5 redirects followed, the 6th response is the throwing redirect), tied to default `maxRedirectHops = 5`. The Rust default must stay 5.
