### Slices A, B notes (contact filter)

- Done: A = 132 tests (32 ported, 100 adapted), B = 193 tests (42 ported, 150 adapted, 1 n-a: the
  coupon "table alias" case; the Rust predicate always reads `"Contact"`).
- `apply_contact_filter(criteria, workspace_id, now)`; `now` (unix ms) replaces `NOW()` (P3.2 rule).
- Filter value windows (`filterValueToUtcInstantWindow`, wall windows) are computed in Rust
  (`value_format.rs`, chrono-tz via `functions::from_wall_ms`) and bound as integer ms or as naive
  `YYYY-MM-DDTHH:MM:SS` text for wall-clock (`::timestamp`) compares.
- Stored custom / bot field text: instant = `round(unixepoch(v, 'subsec') * 1000)`, wall clock =
  `unixepoch(substr(v, 1, 19), 'subsec')` (offset ignored like `::timestamp`), guard = `YYYY-MM-DD`
  prefix GLOB + `unixepoch(v) IS NOT NULL` (for `pg_input_is_valid(.., 'timestamptz')`).
- `isWithinWorkingHours`: the zone's local day / minute / weekday at `now` are computed in Rust and
  bound (the TS bound the zone name into `AT TIME ZONE`).
- Ids bind as INTEGER when they are integer literals, else TEXT (Postgres threw on the cast; SQLite
  matches no row). A non-numeric `ctwaRetarget.integrationWhatsappId` drops the condition.
- The dispatcher now covers every field of the TS `buildConditionWhere` (C1: commerce, C2:
  `sentMessage`, `lastDelivered`, the activity registry fields, D2: `pipelineItem`).

Decisions (orchestrator-delegated, recommended option; to be copied to DECISIONS.md):
- `flow.listNamesWithPrefix` compares the prefix exactly (`substr`), as
  `appointmentCalendar.listNamesWithPrefix` (Postgres `LIKE` is case-sensitive).
- `flow.listWithVersions` without a `sort` is ordered by id; the `with` versions are loaded in
  one query and ordered by id. `findCurrentVersionNodes` returns the `nodes` array elements
  (`Vec<serde_json::Value>`); `None` = flow not in the workspace.
- `file.createdAtCursor` is `toISOString()` of `createdAt` (the column is unix ms; Postgres kept
  microseconds). A cursor text with microseconds is read at ms precision (`parse_iso`); an
  unreadable cursor text is an error. `updateForWorkspace` always sets `updatedAt`.
- inbound-webhook: "now" (`claimedAt`, `processedAt`, purge cutoff) is a parameter. Progress /
  completion fields are `Option<Option<T>>` (`None` = key absent, `Some(None)` = NULL).
  `insertInboundWebhookRequest` runs on the caller's write job (one transaction with the
  counter). `updateInboundWebhook` checks its `set` against the TS `UpdateInboundWebhook` keys
  and always sets `updatedAt`.
- Request rows: every write sets `updatedAt` (Drizzle `$onUpdate`); `release` has no `now`
  parameter (locked signature) and uses `now_ms()`.
- `integrationWhatsapp.listByDisplayPhoneDigits` uses the registered `regexp_replace(.., '\D',
  '', 'g')` and orders by id before `LIMIT 2` (the TS had no order).

## Slice F1: coexist-sync-run (implementer 5, 2026-11-13)

Tests (46, all adapted): `coexist-sync-run-repository` -> `repo_coexist_sync_run_repository.rs`
(12), `coexist-run-recovery-repository` -> `repo_coexist_run_recovery_repository.rs` (17),
`coexist-sync-run-type-scoping` -> `repo_coexist_sync_run_type_scoping.rs` (17). Code:
`coexist_sync_run.rs` (`repository.ts` + `integration-access.ts`). Shared fixtures:
`tests/common/repo10.rs`. One slice: the three files test one module.

- The SQL-text checks (`SET status = 'init'`, `r.type = 'coexist'`, `INTERVAL '10 seconds'`, ..)
  are rows that each fragment picks or spares. `FOR UPDATE SKIP LOCKED` is not ported (one
  SQLite writer).
- "createRun throws when a conflict yields no re-selectable init run": a `BEFORE INSERT`
  trigger with `RAISE(IGNORE)` stands in for the lost race (insert writes no row, no init run).

Decisions (orchestrator-delegated, recommended option; to be copied to DECISIONS.md):
- `NOW()` is `now_ms()` bound once per statement; `NOW() - INTERVAL '10 minutes'` /
  `'10 seconds'` / `'1 hour'` / `make_interval(secs => floor(windowMs / 1000))` are ms
  offsets from it.
- `incrementProgress` returns the affected-row count also without `expect` (the TS returned
  `undefined`); callers without a guard ignore it.
- `updateProgress` / `incrementProgress` `fields` is a `Patch` checked against the 19 TS
  `CoexistRunProgressInput.fields` keys (`PROGRESS_FIELDS`).
- `findIntegrationForCoexist` / `setIntegrationCoexistEnabled` return a
  `CoexistIntegrationRow` enum (Messenger / Instagram / Whatsapp) instead of the row spread
  with `channel`; an unknown channel is an error. The update also writes `updatedAt`
  (Drizzle `$onUpdate`, see slice G1).
- `listContactScanRuns` orders by the parsed sort or `createdAt` DESC, with no id tie-break
  (as the TS).
