namespaces `miniApps` (15), `minigames` (10), `openHours` (4), `orders` (10)
and `paymentProviders` (4) — **43 operations**, list from
`apps/builder/__tests__/__snapshots__/public-spec-operations.test.ts.snap`.

Tests: `conversion/parity/tests/p1-12-miniapps-orders-payments/` — `00-auth`,
`10-open-hours`, `20-payment-providers`, `30-orders`, `31-orders-online`,
`40-minigames`, `50-mini-apps`, `51-mini-apps-whatsapp`. Helpers: `helpers.ts`.

`conversion/parity/src/fixtures/ext/p1-12.ts`, Postgres implementation

## 1. Common contract

### 1.1 Auth (all 43 operations, test `00-auth`)

`workspaceTokenAuthAPIForScope(scope)`; scopes: `mini-apps` (miniApps), `minigames`
(minigames), `ecommerce` (openHours, orders, paymentProviders). Checks run before
input validation:

1. No bearer or an unknown `cbx_ws_` token -> **401** `{defined:true, code:"INVALID_CHATBOT_TOKEN", message:"Invalid or missing workspace API token"}`.
2. Read-only token on any POST/PUT/PATCH/DELETE -> **403** `FORBIDDEN` "Read-only token cannot perform this operation" (before the scope check). Read-only passes on every GET.
3. Token scopes without the route scope -> **403** `FORBIDDEN` "Token is not authorized for the '<scope>' scope".

### 1.2 Errors

- Input validation -> **422** `{defined:true, code:"invalidRequestData", data:{issues:[{path,…}]}}`; path ids (`zodBigintAsString`) that are not digits -> 422 at `id`.
- `ChatbotXException(message, code, status)` -> that status and code; when the exception has `data`, the message gets ` (k=v, k2=v2)` appended (`toDisplayMessage`), and `data` itself is **not** sent (only for 3 structured codes, none here).
- `notFoundException(msg)` -> 404 `notFound` with the fixed message; `validationException` -> 422 `validation`.
- Lists `{data, pageCount}`: `page` ≥ 1, `perPage` 1–50 (`maxLimit`) except `orders.list` (1–100, default 20). `pageCount = ceil(total/perPage)`; **0** for an empty list.
- Responses are **not stripped** to the output schema: `miniApps.delete(Many).whatsappFlows[]` carries `miniAppId` and `flowId` beyond the documented keys (test `51`).

## 8. Untested (with reason)

- Mini App submit, minigame play: public pages with signed tokens, not public API (rows come from the fixture).
- Stripe Connect (OAuth) and PayPal connect: need a platform Stripe credential / UI dialog only; `stripeAvailable:true` path not reachable on parity.
- Online payment completion (Stripe webhook → `paid`, refund on cancel, `orderRefundFailed`, `orderPaidOnline` delete refusal, `paymentProviderInUse` on reconnect to another account): needs signed Stripe webhooks (another unit).
- `orders.export` `truncated:true` (5000+ rows), `paymentExpired` cancel by the expiry scan (30 min).
- Empty PATCH `openHours.update {}` -> **500** in the original (no column to set). Not asserted (rule of P1.3: 500s are not parity). Phase 3 decides (200 unchanged or 422).
- Discount codes / vendor minimums / taxes on orders: covered by P1.7 (discount codes) and P1.14 (vendors, products); order math with tax/discount not asserted here.
- Mini App custom field mappings and contact-variable publish refusal (`contactVariables` message): need a definition editor format; not asserted.
- WhatsApp Flow `refusedLive` (push draft over a live Flow) and Meta error mapping.

## 9. Original behavior the Rust port must match (surprises)

1. `openHours.create` answers **200**, minigames/miniApps create **201**.
2. A `ChatbotXException` with `data` appends ` (k=v, …)` to its message (`toDisplayMessage`), e.g. `providerCode=` with an empty value.
3. Responses are not reduced to the output schema (`whatsappFlows[]` has `miniAppId`, `flowId`).
4. `pageCount` is 0 for an empty list.
5. Order numbers are per workspace, start at 1, and a refused order does not use one; an online order without contact is refused, a cash order is not.
6. `paymentProviders.connectStripeKey` does not offer Stripe at checkout; `disconnect` removes it from `payments.paymentMethods`.
7. Reconnecting the same Stripe account deletes the old webhook with the **new** key; a webhook delete failure never blocks a disconnect.
8. Minigame name conflict is **409** `nameAlreadyExists`; Mini App name conflict is **422** `validation`.
9. `minigames.updatePartial {}` -> 422 with issue path `[]` (refine on the whole object).
10. DELETE routes read their input from the JSON body (oRPC compact input), not the query (`deleteWhatsappFlows`).
12. `orders.list` accepts `perPage` 100 but returns at most 50 rows per page (`parsePagination` clamp).
11. Default store is delivery-only: `shippingType:"pickup"` is refused (400) unless the store offers it.
