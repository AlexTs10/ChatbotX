## 1. Common contract (all 52 operations)

- Auth stack: `workspaceTokenAuthAPIForScope(scope)` — `ads` for `ads.*`,
  `automation` for `aiAgents.*`, `aiFiles.*`, `aiFunctions.*`. Middlewares run
  before input validation, in this order: bearer (or deprecated `?token=`) →
  pre-auth IP limit (600/window) → token lookup (SHA-256) → per-workspace limit
  (120/10 s) → deletion-scheduled check → read-only check → owner quota gate →
  scope check → idempotency → input schema → handler.
  - No token / unknown token → 401 `{defined:true, code:"INVALID_CHATBOT_TOKEN", status:401, message:"Invalid or missing workspace API token"}`.
  - `read_only` token on POST/PUT/PATCH/DELETE → 403 `FORBIDDEN`, message
    `Read-only token cannot perform this operation`. Exception: POST
    `/v1/ads/campaigns/insights` (`ADS_CAMPAIGNS_INSIGHTS_PATH`) is allow-listed.
  - Token with a `scopes` list that lacks the route scope → 403 `FORBIDDEN`,
    message `Token is not authorized for the '<scope>' scope`.
- Input schema failure → 422 `{code:"invalidRequestData", data:{issues:[{path,message,…}]}}`
  (oRPC `BAD_REQUEST` remapped in `toKnownOrpcError`). Query strings are coerced
  by `SmartCoercionPlugin` (numbers, booleans). Path ids use `zodBigintAsString`
  (non-numeric → 422, path `["id"]`).
- `ChatbotXException(message, code="systemError", status=400)` → its code/status;
  `SdkException` (Graph `FacebookAdsException`) → `BAD_REQUEST` with the Graph HTTP
  status and the public Graph message (`(#<code>) <message>`); unknown errors → 500
  `INTERNAL_SERVER_ERROR`.
- Every row is scoped by the token's workspace: an id of another workspace behaves
  like an unknown id. Responses never carry `workspaceId` for `ads.*`.
- Third-party traffic of `ads.*` goes to `https://graph.facebook.com/v23.0/…`
  (ky, 30 s timeout, GET retried 3× on 408/429/5xx). `access_token` is a query
  parameter on GET/DELETE/multipart, a JSON body field on JSON POSTs. All of it is
  answered by the fake upstream; `tests/smoke/99-interception.test.ts` must stay
  green in the same run.

### Common rules (all 17 operations)

Source: `apps/builder/src/features/{ai-agents,ai-functions,ai-files}/api/public.ts`,
`apps/builder/src/orpc.ts`, `apps/builder/src/middlewares/workspace-token-auth.ts`.

- Auth: `workspaceTokenAuthAPIForScope("automation")`. Order: token check, pre-auth
  IP rate limit (600/window), per-workspace rate limit, read-only check, owner
  quota gate, scope check, idempotency, then input validation, then handler.
  - No / unknown token → 401 `INVALID_CHATBOT_TOKEN` (before input validation).
  - Token whose `scopes` list lacks `automation` → 403 `FORBIDDEN`,
    message `Token is not authorized for the 'automation' scope`.
  - `read_only` token on POST/PUT/PATCH/DELETE → 403 `FORBIDDEN`, message
    `Read-only token cannot perform this operation` (no POST of these namespaces
    is in `READ_ONLY_TOKEN_ALLOWED_POST_PATHS`, so `aiFiles.search` and
    `aiFiles.reindex` are blocked too). GET works.
- Input-schema failure → 422 `invalidRequestData`, `data.issues[]` (zod issues).
  Path ids use `zodBigintAsString` (a non-numeric id → 422).
- `ChatbotXException` → its code/status (`notFound` 404, `validation` 422, ...).
- Rows are scoped by `workspaceId`: another workspace's id behaves like an unknown id.
- Timestamps are ISO strings; ids are snowflake strings.
- Paged lists (`publicListRequest`): `page` ≥ 1 (default 1), `perPage` 1–50

### Not tested black-box (AI part)

- `aiFiles.reindex` `coalesced: true` and 409 `conflict`: need a processing run that is
  still active when the call arrives. The worker finishes a run in milliseconds and
  makes no third-party call during the run (embedding is a later job), so the state
  cannot be held open from outside without a race.
- `processingRun.error = enqueueFailed` (create) and 502 `systemError` (reindex queue,
  storage failure): need a Redis or S3 outage.
- 429 rate limits of `aiFiles.search` / `aiFiles.reindex` (~30/min): not tested, to
  keep the run short; the limiter is shared code (`assertApiNotRateLimited`).
- Template-lock refusals (`assertResourceEditable`, `withDeleteGuard`): need installed
  templates (other unit).
- `aiFunctions` `triggerFlowId` that points at an existing / missing flow: needs a flow
  (flows unit); only the schema rule (numeric string) is tested.

## 5. Harness notes

- The fake upstream matches scripts by host/method/path/body only, not by query.
  Two Graph GETs on the same path with different `access_token` values (for example
  `/v23.0/me/adaccounts` for a messaging connection and for the workspace
  connection) are told apart by script order and `times: 1`, with one call in
  flight at a time. A `match.query` option would make this simpler (optional
  orchestrator change; not needed for this unit).
- Run with the interception self-check:
  `run-original.sh --no-build -- tests/p1-02-ads-ai tests/smoke/99-interception.test.ts`.
