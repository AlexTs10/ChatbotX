## Security

- Amounts and currency come from the order rows the server priced; the
  client sends product ids and quantities only. A paid status is accepted
  only when the provider's minor units and currency equal the attempt's
  (`applyStatus`); any mismatch, or money for an order that no longer waits,
  is refunded (key `refund-{paymentId}`, never twice).
- The provider is always asked again (`getCheckoutStatus`); a webhook body
  only names the attempt. Stripe: `Stripe-Signature` HMAC-SHA256 with the
  300 s tolerance (`constructEvent`); PayPal: `verify-webhook-signature`
  with the raw body. Bad signature 400, no stored secret 404.
- Provider secrets (Stripe key + webhook secret, PayPal client id / secret +
  webhook id) are stored with `Encryption::encrypt_object`, AAD
  `ecommerce-payment:{workspaceId}:{provider}`; never returned.
- Provider hosts are constants (`api.stripe.com`, `api-m[.sandbox].paypal.com`);
  no user URL is fetched, so no SSRF guard is needed.
- `/v1` routes: workspace token with the `ecommerce` scope (route table).
- Webhook receivers are not rate-limited (the original has no limiter there).
