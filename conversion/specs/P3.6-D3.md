`automated_response::Updated::changed` / `StatusChange` / the deleted ids
(+ the `*_audit` detail texts), `message::Outgoing` (stored message,
realtime `messageCreated` payload, jobs). The handlers call
`state.record_audit`, `state.jobs` and `state.queue_realtime`.

## Decisions

- Recommended option: the services return audit decisions / jobs /
  realtime payloads instead of taking `ApiState` (the business crate has no
  `ApiState`; same pattern as the X1 wiring of the D1 / D2 domains).
- `keywords.create` with a missing reply flow answers the `notFound`
  "Flow not found" of the template guard `assertReferencable` (it runs
  before `flowService.exists`), as parity `40-keywords-crud` shows; the TS
  unit test mocked the guard (422).
- No template locks / guards and no rule cache (as P3.6-D1 / D2).
- `keywords.list` sorts `createdAt` desc, then `id` desc (tie-break; rows
  made in the same ms).
- `findByInboundKeyword` matches one whole JSON array element; the lowest
  id wins (the original has no order).
- The default-reply throttle (`default-reply/throttle.ts`, 7 TS cases)
  needs the unported `automationThrottleService`; only the worker uses
  both. Moved to the flow runtime unit.
- `createOutgoing` is reduced to text, flow and the product refusals. The
  product branch: a comment / private reply is refused (422 `validation`);
  a channel without a catalog source is `productMessageUnresolvable`
  `channelUnsupported` (only WhatsApp has one); a WhatsApp product send
  answers 501 `notPorted` until the Meta catalog slice ports
  `prepareOutgoing` (P3.6-D1 decision, "Product imports / Meta catalog").
- Attachment URLs are not presigned (`resolveMediaUrl` /
  `resolveAttachmentFallbackUrl` not ported): `url` / `fallbackUrl` are
  `null`. Text messages have no attachments, so the parity output is equal.
- The job payloads carry the conversation / contact inbox as a reduced
  JSON object (id, workspace, contact, inbox, channel, source ids, routing
  fields), not every column; the jobs wait for the worker port.
- Locked test `contacts_messages_public_api.rs:124` (products on webchat)
  expected 204; reported to the orchestrator, who changed it to the real
  422 `channelUnsupported` on `conversion`.
- Contact messages with media (`files`, `mediaFile`, `mediaFileId(s)`)
  answer 501 `notPorted` (the media upload / library path is not ported
  in this unit).
- Locked test `contacts_messages_public_api.rs` seed: the conversation gets
  `createdAt` 0. `findForContact` only reads messages from one hour before
  the conversation start (`getSafeSinceTime`); the TS test mocks the
  service, and the seeded message is at 1 s. Fixture only, no assertion
  changed.

- Conversations (slice 3): `chatbotx_business::conversation_list`
  (`listConversations`, `findConversation`, `buildConversationWhere` as SQL
  over `Conversation c JOIN "Contact"`) and `conversation_actions` (assign,
  archive, follow, bot, read, unread); `handlers::conversations` (12 routes).
  Workspace tokens only: no member scope or email / phone masking.
  `threadControl` answers 501 `notPorted` (needs the channel thread-control
  registry; parity `03-conversations-thread-control` moves with it).
- The actions write the row and return the realtime envelope
  (`conversationAssigned`, `conversationUpdated`) and the
  `notifyConversationAssigned` job. Not ported (no service yet): the
  conversation flow-trigger events, `analytics:dashboard`, response-SLA
  window tracking on assign, thread release on archive, the quick-reply
  follow-up cancel on a bot pause, and cache invalidation (no cache).
- `u_<id>` / `t_<id>` with a non-numeric id: invalidAssignee 400 / notFound
  404 (Postgres would fail the bigint cast with a 500).
- The `jsonQueryParam` decode does not run `decodeURIComponent` a second
  time (a literal `%` in a JSON filter value is kept).
- Conversation avatars keep a stored key raw (`(key) => key`), as
  `resolveConversationContact`; `resolve_contact_avatar_url_with` takes the
  finalize function.
- Slice messages: `business::message_actions` (`findByIdWithUrls`,
  `resolveContactInboxForConversation`, `deleteMessage`,
  `changeMessageAttributes`, `editMessage`) and `handlers::messages`
  (9 routes). The send body parser is shared with `contacts.sendMessage`
  (media library / device files 501 `notPorted`). A new attachment on edit
  (`newAttachmentPath`, needs storage and image dimensions), the WhatsApp
  Flow response view (Meta Flow labels), WhatsApp templates and call
  permission answer 501 `notPorted`; `removeAttachment` is ported.
- `messages.delete` / `update` / `changeAttributes` return the realtime
  envelope and the chat job (`deleteChannelMessage` only for a message
  with a `sourceId`, `editChannelMessage`, `changeChannelMessageState`);
  the caller publishes / adds them.

## Behaviour differences

- No audit actor in `handlers::dispatch` tests (as X1).
- No `agent:replied` metric / `markAgentReplied` (working-hours unit).
- No quick-reply buttons, media files, image limits, private-reply
  conversation (`findOrCreate`), routing-bypass flag.
