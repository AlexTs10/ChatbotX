# P3.1 — shared backend packages in `crates/core` (porter spec)

Unit: port `packages/utils`, `packages/encryption`, `packages/variables` (without JavaScript interpolation), `packages/logger` and `packages/decision-config` into `crates/core` (`chatbotx-core`). Backend-used parts only. Dependency order kept: `db <- kv <- {jobs, rt} <- core <- {api, server}`; core uses `chatbotx-kv` (clock, in-process cache) and nothing above it.

Test map: `conversion/specs/P3.1-test-map.tsv` (81 frozen files: 80 class C + `interpolate-into-javascript.test.ts`, dropped).

## 2. Crate choices

- `ring` 0.17: AES-256-GCM, HMAC-SHA256, SHA-256, `SystemRandom`. Base64url is hand-written (strict encode, Node-lenient decode).
- `chrono` + `chrono-tz`: IANA offsets. The accepted zone *names* are the `Intl.supportedValuesOf("timeZone")` list of Node 24.22.1 / ICU 78.3 (418 names, no `UTC`, `Asia/Saigon` not `Asia/Ho_Chi_Minh`) plus offsets; names are case-insensitive (own map over `TZ_VARIANTS`, no extra chrono-tz feature).
- `regex`; `icu_normalizer` 2 (NFD for `normalizeForMatch`, already in the tree via `url`/`idna`); `url` (WHATWG URL / `URLSearchParams` form encoding).
- Images (sharp in the original): `image` 0.25 (decode jpeg/png/webp, EXIF orientation, Lanczos3), `jpeg-encoder` 0.7 (4:4:4 + optimized Huffman for media), `webp` 0.3 (libwebp lossy, avatars); `bytes::Bytes` so an unchanged image is the same buffer.
- `tokio` (`OnceCell`, `join!`, timers), `futures` (std only), `http`, `serde`/`serde_json`, `tracing`.
- Dev: `tracing-subscriber` (`RecordingLog` capture layer), `image` with `gif` (fixtures), `chatbotx-kv` `test-util` (cache inspection).

## 3. Behaviors that must match exactly

### 3.1 Encryption byte compatibility (stored data must still decrypt)

- Key = the 32 raw bytes of the 64-hex `ENCRYPTION_KEY` (no KDF); rotation keys `ENCRYPTION_KEY_PREV` / `ENCRYPTION_KEY_ID` (default `default`). Decrypt key choice (no trial decryption): `kid` = active id → active key; else `ENCRYPTION_KEY_PREV` when set; else (no `kid`) the active key; else `NoKey`.
- IV 12 random bytes; tag 16 bytes; Web Crypto's `ciphertext‖tag` is split into `text` and `tag`; AAD = UTF-8 of `aad` (absent = empty).
- Blob JSON field order `{"v":1,"kid":…,"iv":hex,"text":hex,"tag":hex,"aad"?:…}`, lower-case hex. Tokens = base64url without padding of that JSON; decode is lenient like `Buffer.from(…, "base64url")` (both alphabets, padding and junk skipped).
- Known-answer vector (unit test in `encryption`): key `0123…cdef`, IV `000102030405060708090a0b`, `"hello"`, aad `org:1:whatsapp` → text `e961f67169`, tag `a40c222f38f76dc392e01e010804cc2a`.
- HMAC signatures (`signUserHash`, `signMeLink`, `signOpenLinkUrl`) use the raw key bytes; the hex key is decoded like `Buffer.from(hex, "hex")` (stops at the first bad pair).
- Error messages are the original texts (`EncryptionError` `Display`).

### 3.2 Variable interpolation

- Grammar: `\{\{(coupon:[^{}\n]+|raw:[^{}\n]+|[^{}\n]+)\}\}`. Names are JS-trimmed; unknown names stay literal (`{{x}}`), known names with no value render `""` (never `null`/`undefined`).
- Resolver order: system field, `raw:` custom field (untrimmed name after `raw:`, verbatim value), `bot_field:<digits>` (exact token, not trimmed inside; only ids present in the map), custom field (rendered: temporal types in the contact zone → workspace zone → UTC; `date` keeps the literal day), `pipelines.<ref>.<attr>`, `coupon:<topic>`.
- `{{gender}}` (sentence case on in `replaceAll`): the label (`resolveGenderLabel` by **workspace** language, primary subtag, English fallback) is kept after start / `.!?…` / newline (with optional quotes/brackets/spaces), lowercased elsewhere.
- `escape_value` is applied to each resolved value before interpolation. Any resolver failure → logged `Unable to render custom fields to message` and `VariableError::Render`.
- Deep replace: spintax (opt-in) runs before the variable pass, so contact data is never spun; contact data loads only when some leaf contains `{{`; the input is never changed.
- Pipeline loader: one load per context, shared across `replace_all` calls, never started when no pipeline variable is read; a failed load fails only a render that reads a pipeline variable.

### 3.3 Dates and time zones

- The process zone is UTC (as the servers run). `getSafeSinceTime(t, 1y)` floors `t − 1y` to the UTC hour (the original uses `setMinutes(0,0,0)` in the local zone).
- `Intl` accepts offsets `+07:00`, `-0700`, `+07`, any case; `US` is invalid. `fromZonedTime` maps a DST gap forward by the gap (NY 02:30 → 06:30Z) and an overlap to the earlier instant.
- `Date.parse` is V8's: no trimming, 1–2 digit month/day, `T`/`t`/space, `Z`/`z`, `±HH:MM`/`±HHMM`, `24:00` allowed, `+07` invalid.
- `formatInTimeZone` with an unparseable string fails (`Invalid time value`); `formatWithFallback` never fails (zone → UTC → raw text / `""`).
- Stored contact zones: an offset (`"7"`, `"+07:00"`, `"-5"`) maps to the `offsetToTimezoneMap` zone; `{{timezone}}` renders the signed offset (`+7`, `-5`, `0`, `+5.5`), from an IANA zone at "now".

### 3.4 Phone-number normalization non-determinism (parity finding)

Not a libphonenumber problem: `+15550001111` normalizes the same for every region (probed on Node 24). Cause: `packages/business/src/contact/update-from-message.ts` scans every inbound message **text** for phone numbers (`extract-contact.ts`, countries VN/PH/KH/ID/US/TH) and overwrites `Contact.phoneNumber`. The parity test `06-channels-api.test.ts` sends `hello ${uniqueId()}` (base36 timestamp + random hex); that text sometimes holds a digit run such as `8864158`, which becomes `+848864158`. The parity flake comes from the fixture text, not from normalization. Fix belongs to the business port / the parity fixture (owner decision), not to P3.1.

## 4. Differences and doubtful points

1. `serde_json` is used without `preserve_order` (feature unification would change other crates): JSON objects built by core (e.g. `json_stringify` of a `Value`, deep-replace output) have sorted keys, where JS keeps insertion order. Values are equal; byte output of re-serialized objects can differ.
2. Images: `jpeg-encoder`/libwebp output is not byte-identical to sharp/mozjpeg; the tests check dimensions, format, size bounds and "unchanged = same buffer". Size thresholds (`minSavingPercent`) can decide differently on borderline inputs.
3. `withCache`: the real cache does not store `None` (the original's real `withCache` does not either; one test mock did). A failed profile-snapshot fetch is retried on the next render.
4. `resolveContactAvatarUrl` / `resolveMediaUrl` (business `media`) stay behind `VariableSources::resolve_contact_avatar` / `resolve_attachment_media_url`; core only makes the storage key public. The business port must implement the sentinel / proxy logic there.
5. Recurrence with an invalid time zone falls back to UTC (the original throws later in date-fns); the step limit returns `Err` instead of throwing.
6. `media-download`: no HTTP client in core; `MediaFetcher` trait (the server wires `reqwest`).
7. Logger: log field names are snake_case (DECISIONS P2.6); `redact` depth limit 64; pino `err` serializer → `LoggedError`.
8. Exhaustiveness: a new `SystemFieldType` without a match arm is a compile error (no runtime "Unhandled system field" branch).
9. Not ported because nothing on the backend uses them: `AI_HANDOVER_CHANNELS`, `SymbolicSnowflakeIDs` (no importer); `getIdFromParams` (Next.js page params, builder pages only); `utils/keys.ts` (`createEnv` schemas: the readers take `Env` directly, `image_optimize_settings` / `live_media` parse the same variables with the same defaults and bounds).
10. Small backend-used utils without frozen tests (`broadcast`, `cache-keys`, `contact-filter-value-format`, `conversation`, `encode`, `has-link`, `levenshtein`, `no-avatar-sentinel`, `referral`, `CONTACT_SCAN_CHANNELS`, google-click capture-source map, `selfServeSecretSchema`) are ported in stage 2 with own unit tests.
