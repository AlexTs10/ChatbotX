## 7. Slice idempotency (`Idempotency-Key`, third run)

| TypeScript | Rust |
|---|---|
| `lib/idempotency/api-idempotency.ts`, `constants.ts` | `chatbotx_api::idempotency` (claim / complete / release over `CasStore`) |
| `middlewares/idempotency.ts` | `idempotency::api_idempotency_middleware`, run in `routes::handle_public_request_with` around the workspace-token and channel-token handlers |

Storage: `DurableKv` (kv K11, durable CAS), key
`api-idempotency:<apiCredentialId>:<route id>:<key>`; `apiCredentialId` is
`api-token:<id>` / `mcp-oauth:<client>` / mobile / `channel-api:<id>` from the
auth context. Stage 1: 24 tests (3 ported, 21 adapted; 3 n-a rows: the
templates install route is not ported). The orchestrator fixed one locked
test (f77e7c9aa, JSON 500 body). Stage 2: business + api 702 passed, 0
failed; clippy, fmt clean. Parity: p1-05 `02-connections-api-channel` all
pass; p1-06 `01-crud` 15/19 (was 14/19; open: PATCH / PUT need
`POST /v1/custom-fields`, delete needs `GET .../tags`, block needs
`/v1/analytics/blocked-contacts-count`).

Differences:

1. The record also stores the HTTP `status` of the first answer; a replay
   answers with it (the original answers with the route success status,
   which is the same value).
2. The three idempotency errors are always `defined: true` (the original
   is `defined` only on routes whose error map lists them; every write map
   used so far lists them).
3. A 2xx answer whose body is not JSON (file download) releases the key
   (the original stores any JSON-serialisable output).
4. The fingerprint is over the raw input (path params merged with the JSON
   body; a body that is not JSON as `__raw__:<sha256>`); serde number text
   (`1.0`) can differ from JS, which only changes the hash value.
5. Mobile-user routes get the middleware with the P3.5e mobile auth.

### Decisions (P3.6-D2 idempotency)

- The middleware builds a `DurableKv` over `ApiState.db` with `SystemClock`
  per call (the `ApiState` literal of the locked fixtures has no kv field);
  expired rows are skipped on read and swept by the `Kv` sweeper.
- Infra: the Dell `/tmp` (tmpfs, 7.8 GB) was 81 % full with 506 stale test
  directories (more than 60 minutes old); 316 business tests failed in
  `Db::open`. Removing the stale directories fixed it (702/702).
