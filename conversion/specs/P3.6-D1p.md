## 1. Layout

- `crates/business/src/pipeline/`: `access` (scopes, permissions), `naming`,
  `currency` (+ `currency-refresh`), `settings` (`mergePipelineSettings`; the
  parse half is `chatbotx_db::repo::partials::pipeline`), `events`
  (`pipelineItemChanged` events), `service` (pipeline CRUD, access checks,
  `canViewPipeline`), `structure` (stages, custom fields).
- `crates/api/src/handlers/pipelines.rs`: the `pipelines.*` public routes. A
  workspace token acts as `PIPELINE_TOKEN_SCOPE` (`WorkspaceToken`, bypasses
  the ACL); the actor has no user id.

## 2. Slices

1. structure: pipelines list / get / create / update / delete / duplicate,
   stages create / update / reorder, fields CRUD; naming, currency, access,
   settings merge, `canViewPipeline`.
2. items: create / get / update / move / transfer / delete, `deleteStage`
   drain, mutation engine, item fields, assignees, money in / out.
3. query: listItems / stageTotals / listContactItems, item filter, field filter.
4. members + content: setMember / listMembers / removeMember, comments,
   attachments, activity, media scope.
5. analytics + flow actions: getStats, flow actions, flow publish check,
   variable targets.

## Decisions

- No list cache (`withCache`), no audit log, no template guards
  (`withTemplateLockedTransaction`, `assertResourceEditable`,
  `assertDeletable`, `assertContentCopyable`; DECISIONS 2026-11-13: template
  unit). Advisory locks are not needed (one SQLite writer).
- Realtime: the business crate has no realtime handle. Services return the
  `pipelineItemChanged` events (`events::PipelineItemChanged`);
  `notify_workspace_currency_change` returns them. The API layer does not
  publish them yet (the `ApiState` fixture has no realtime field), so the
  parity realtime test fails until a realtime handle is wired.
- `resolveWorkspaceDefault` on a missing workspace gives USD / no country (the
  TS threw `notFound` from `workspaceService.findById`).
- Token actor: `actorSourceId` (the API token id) is `None`: `handlers::Call`
  has no token id.
- DELETE routes read a JSON body when one is sent, else the query.
- `deleteStage` in slice 1 checks the stage (missing, last stage, busy,
  bad destination) and removes an empty stage; the item drain comes with
  slice 2.
- Slice 2: `deleteStage` always drains in the request (no
  `processPipelineStageBulk` job; `queued` is always false, `jobId` null).
- Slice 2: the flow-trigger events (`pipelineItemCreated`, `...MovedToStage`,
  `...ValueChanged`, `...StatusChanged`, `...PriorityChanged`) are built as
  `PipelineEffect::Event` (metadata money in major units) but not dispatched:
  the event bus is not ported. The `assignContact` effect (conversation
  assignment after an assignee change) is not ported (conversation service).
- Money in the API: input major units -> `round(value x 10,000)`; output
  stored / 10,000 as a JS number.
- Custom field values are normalized with
  `contact_custom_field::normalize_value_for_storage` (contact, then workspace
  zone); an error or a `None` result is "Invalid value for <field>".
