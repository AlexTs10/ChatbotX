## 1. Layout

- `crates/business/src/pipeline/`: `access` (scopes, permissions), `naming`,
  `currency` (+ `currency-refresh`), `settings` (`mergePipelineSettings`; the
  parse half is `chatbotx_db::repo::partials::pipeline`), `events`
  (`pipelineItemChanged` events), `service` (pipeline CRUD, access checks,
  `canViewPipeline`), `structure` (stages, custom fields).
- `crates/api/src/handlers/pipelines.rs`: the `pipelines.*` public routes. A
  workspace token acts as `PIPELINE_TOKEN_SCOPE` (`WorkspaceToken`, bypasses
  the ACL); the actor has no user id.

## 2. Slices

1. structure: pipelines list / get / create / update / delete / duplicate,
   stages create / update / reorder, fields CRUD; naming, currency, access,
   settings merge, `canViewPipeline`.
2. items: create / get / update / move / transfer / delete, `deleteStage`
   drain, mutation engine, item fields, assignees, money in / out.
3. query: listItems / stageTotals / listContactItems, item filter, field filter.
4. members + content: setMember / listMembers / removeMember, comments,
   attachments, activity, media scope.
5. analytics + flow actions: getStats, flow actions, flow publish check,
   variable targets.

## Decisions

- No list cache (`withCache`), no audit log, no template guards
  (`withTemplateLockedTransaction`, `assertResourceEditable`,
  `assertDeletable`, `assertContentCopyable`; DECISIONS 2026-11-13: template
  unit). Advisory locks are not needed (one SQLite writer).
- Realtime: the business crate has no realtime handle. Services return the
  `pipelineItemChanged` events (`events::PipelineItemChanged`);
  `notify_workspace_currency_change` returns them. The API layer does not
  publish them yet (the `ApiState` fixture has no realtime field), so the
  parity realtime test fails until a realtime handle is wired.
- `resolveWorkspaceDefault` on a missing workspace gives USD / no country (the
  TS threw `notFound` from `workspaceService.findById`).
- Token actor: `actorSourceId` (the API token id) is `None`: `handlers::Call`
  has no token id.
- DELETE routes read a JSON body when one is sent, else the query.
- `deleteStage` in slice 1 checks the stage (missing, last stage, busy,
  bad destination) and removes an empty stage; the item drain comes with
  slice 2.
- Slice 2: `deleteStage` always drains in the request (no
  `processPipelineStageBulk` job; `queued` is always false, `jobId` null).
- Slice 2: the flow-trigger events (`pipelineItemCreated`, `...MovedToStage`,
  `...ValueChanged`, `...StatusChanged`, `...PriorityChanged`) are built as
  `PipelineEffect::Event` (metadata money in major units) but not dispatched:
  the event bus is not ported. The `assignContact` effect (conversation
  assignment after an assignee change) is not ported (conversation service).
- Money in the API: input major units -> `round(value x 10,000)`; output
  stored / 10,000 as a JS number.
- Custom field values are normalized with
  `contact_custom_field::normalize_value_for_storage` (contact, then workspace
  zone); an error or a `None` result is "Invalid value for <field>".
- Query slice: `toItemFilter` / `toItemListQuery` live in the API layer
  (`handlers::pipelines::item_list_query` / `item_filter_query`, raw query
  -> repository filter); money filter amounts become x 10,000 there. An
  empty `field_conditions` map stands for "no conditions". The zod
  `superRefine` runs only when the object parsed (as zod).
  `listForContact` takes the viewable pipelines from
  `list_with_permissions`. The contact `channel` of a card
  (`listLatestAnalyticsAttribution`) is not ported (no public field uses it).
- Token actor: `actorSourceId` is now the API token id (`call.token_id()`,
  X1 0e3f525c5); this replaces the earlier `None` decision.
- Content slice: comments / attachments / activity follow
  `item-content.service.ts`; realtime events are returned
  (`ItemMutation.events`) and not published (X1 wires realtime).
- The media-library domain (`createUploadUrl` with a local signed PUT
  route, `createFile`, `getFile`) is NOT part of D1p: it needs a new
  handlers module, a PUT route in crates/server and the `chatbotx-files`
  `Uploader` wiring in `ApiState`. Recommended: its own unit (media
  library). Until then the parity attachment test fails on
  `/v1/media-library/files/upload-url` ("not ported").
- Analytics: `parseAnalyticsDateRange` is ported in
  `pipeline::analytics` with chrono-tz. A zone name must match exactly (no
  case-insensitive alias lookup, `default-features = false`); an unknown
  one is UTC. A skipped local midnight (DST gap) moves forward by hours.
- Flow publish check: `pipelineStepSchema.safeParse` is reduced to the
  fields the check reads (string `pipelineId`, `fieldValues` of string
  pairs); a non-numeric pipeline id has no fields. The flow publish path
  (D2 `flow_version`) does not call it yet.
- `variable-targets-light` is not-applicable (JS import graph).
- Flow actions (`pipeline::flow_actions`): the step / trigger action is the
  flow-config JSON (`&Value`, string ids checked with `is_bigint_id`).
  `interpolate` is an `Arc<dyn Fn(String) -> boxed future>` (`interpolate_fn`
  wraps a plain function). `PIPELINE_FLOW_ACTION_HANDLERS` is the list of
  action names; the handlers are a `match`. `flow_id` is an `i64`; the actor
  `sourceId` is its decimal string. The result also carries the realtime
  events and flow-trigger events of the write; the caller publishes them (the
  business crate has no realtime handle or event bus). `changeValue` stores
  `round(value x 10,000)`; due dates use `js::parse_date` (unix ms). A
  repository error is `Err` (the job retries); every `BusinessError::Exception`
  is the `error` result with its message.
- The builder test `pipelines-actions-parity` (11) is deferred to Phase 4: it
  checks Next.js server actions (`workspaceActionClient(AllowExpired)`, the
  session scope) against the public handlers, and server actions become Rust
  routes only in Phase 4 (DECISIONS 2026-11-11). No Rust code exists to test.
